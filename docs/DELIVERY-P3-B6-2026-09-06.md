## 一、本批目标与边界

### 1.1 目标（DESIGN §9 G1）

1. **customer 划扣内部端点**：`POST /api/customer/internal/cards/writeoff`（X-Internal-Token 系统身份），customer 卡台账成为唯一动账方——行锁找卡、校验在用/次数/余额（422 中文）、扣 remainTimes + balance、次数扣尽置「已用完」、始终写 CONSUME 流水（纯扣次写 0 额锚点行）；WO 单号为 bizRef 幂等键，重放返回既有流水不双扣；`backfill=true` 回填模式只补流水不扣卡。
2. **查询端点**：`GET /api/customer/internal/cards/writeoff-ledgers?bizRefs=WO…,WO…` 供 txn 双账核对读取（禁直读别域表）。
3. **txn 两条划扣路径联动**：M4FlowController 直划与 WriteoffDeskService 工作台划扣均改为「WO 单号先行生成 → customerCardClient.writeoff(...,false) 权威扣卡 → 落 writeoff_record → outbox 资金事件 → 审计」；customer 返回 4xx 中文透传、5xx/网络故障转 502「本笔操作已回滚，未扣款未记账」，失败即中止回滚（资金安全反向失败中止红线）。
4. **双账核对**：`GET /api/txn/internal/writeoff-reconcile`（权限 internal:finance-flow，干跑只读）——按 writeoff DONE 单逐笔比对 customer 卡台账，报三类差异：MISSING_LEDGER（customer 无 WO 流水）/ CARD_MISMATCH（流水落在别的卡）/ AMOUNT_MISMATCH（ledger.amount ≠ -w.amount）；customer 不可用直接 502，绝不出假「全部一致」。
5. **存量回填**：`POST /api/txn/internal/writeoff-backfill`——回填前双账快照（before）→ 逐笔调 customer backfill=true（4xx 收集 skipped 转人工不中断；5xx/502 立即 ABORTED 中止，已补笔 WO 幂等可重跑）→ 回填后快照（after）→ 仍有差异返回人工调平 warning（禁止自动改数）；全程 WRITEOFF_RECONCILE / WRITEOFF_BACKFILL_RUN 审计。

### 1.2 边界红线（本批不碰，移交 B7）

- DESIGN §9.1 三方对账（finance 分录参与的全量对账）：本批只做 txn writeoff ↔ customer card_ledger 两方卡账核对。
- DESIGN §9.2 settlement 封账（日结/月结封账期）：未做。
- DESIGN §9.3 网关 `/api/*/internal/**` 网络层隔离：本批内部端点仅靠 X-Internal-Token + 权限码保护（与既有内部回调同口径），网关层路由隔离列 B7。

## 二、改动清单

### 2.1 customer-service（卡台账权威动账）

- `InternalCardController.java`：新增 `POST /cards/writeoff`（权限 internal:card-write）与 `GET /cards/writeoff-ledgers`（权限 internal:card-balance），挂载于既有 `/api/customer/internal`。
- `CardLedgerService.java`：
  - 新增 `writeoff(cardNo, writeoffId, timesUsed, amount, storeCode, backfill)`：正常分支行锁 → 校验在用/次数 ≥ 扣次（422）/余额 ≥ 扣额（422）→ 扣 remainTimes、扣 balance（amount=0 纯扣次不动余额）→ 扣尽置「已用完」→ 写 CONSUME 负额流水（bizRef=WO 单号、order_no 留空——划扣非订单收款，不参与订单退款回加防超退口径）；回填分支不校验卡状态（已用完/已退卡同样补记）、不动次数/余额、balance_after 取回填执行时余额、operator=system-backfill。
  - 纯扣次（amount=0）同样写一行 amount=0 的 CONSUME 流水：0 额不破坏 Σamount=balance 恒等式，且为 WO 单号提供幂等锚点（否则纯扣次重放无流水可查会双扣次数）。
  - **连带缺陷修复（见 §5.1）**：6 处 audit.record 的 payload 由中文散文改为 ObjectMapper 序列化的合法 JSON（Map 结构 + summary 文案字段），新增 `json()/writeoffPayload()/backfillPayload()` 辅助方法。
- `CardLedgerRepository.java`：新增 `findByBizRefIn(List<String>)`。

### 2.2 txn-service（联动 + 核对 + 回填）

- `CustomerCardClient.java`（B6 前段已就位，本批复验）：`writeoff(...)` POST customer 内部划扣端点（body 含 backfill）；`writeoffLedgers(...)` GET 拼 bizRefs；post 4xx 透传中文 / 5xx+网络转 502「本笔操作已回滚，未扣款未记账」；读路径 502 文案「双账核对失败：…（本次未执行任何写入）」。
- `M4FlowController.java` / `WriteoffDeskService.java`：两条划扣路径改为 WO 单号先行（WriteoffNoGenerator 基于 writeoff 表当日 maxSeq+1，回滚重试同号幂等）→ customer 权威扣卡 → 落库；审计 payload 标 `"authority":"customer"`。
- `InternalFinanceController.java`：
  - 新增 `GET /writeoff-reconcile`：参数 storeCode/from/to 可选（from 当日 00:00、to 次日 00:00，UTC 日界）；`reconcile(spec)` 核心——writeoffRepo 扫 DONE 且 cardNo 非空，customerCardClient.writeoffLedgers 批量取流水按 bizRef 建索引，逐笔裁决三类差异，返回 ReconcileResult(totalDone/okCount/diffCount + 三类差异清单)。
  - 新增 `POST /writeoff-backfill`：runId=WBR+时间戳；before=reconcile → 审计 before-backfill 快照 → 逐笔 backfill：4xx（卡 404/WO 冲突 409）收 SkippedDiff 不中断，5xx/502 审计 ABORTED 后 rethrow → after=reconcile → diffCount>0 时 warning「仍有 N 笔双账差异…禁止自动改数，请人工调平」→ 审计 DONE。
  - 6 个 record：BackfillCmd / ReconcileResult / WriteoffDiff / BackfillResult / BackfilledItem / SkippedDiff。
  - 既有 finance-flows 投影端点与各 Spec 方法不动。

## 五、问题与教训（归档必录）

### 5.1 🔴 连带缺陷：customer CARD 域审计全量 500（audit_log.payload 为 jsonb，散文 payload 被 PG 拒绝）

- 现象：B6 验证中 `select … from audit_log where biz_type='CARD'` 恒为 0 行；customer 容器日志大量「审计追加失败 bizType=CARD … : 500」（RECHARGE/CONSUME/REFUND/WRITEOFF/WRITEOFF_BACKFILL 全中，B6 前即存在）；audit-service 日志根因 `PSQLException: invalid input syntax for type json，Token "存量划扣回填补记流水：划扣单" is invalid`。
- 根因：audit_log.payload 是 **jsonb 列**；txn 侧审计传手工拼的 JSON 字符串正常，而 customer `CardLedgerService` 6 处 audit.record 把中文散文直接当 payload，PG 拒绝 → audit-service 500。RestAuditRecorder 失败仅 log.error 不阻断业务，故业务全对、审计全丢，长期未被发现。
- 修复：6 处 payload 全部改为 ObjectMapper 序列化的合法 JSON（LinkedHashMap/Map.of 结构化字段 + summary 中文文案字段）；新增 json()/writeoffPayload()/backfillPayload() 辅助，序列化失败兜底 "{}"。
- 教训（已入铁律意识）：**审计 payload 必须为合法 JSON**；新写接口后必须 `select audit_log` 亲眼确认落库，不能只看业务返回 200。
- 历史影响：B6 前 customer CARD 域审计（充值/消费/退款/退卡）在 prod/seed 均未落库；修复后新发生的 CARD 事件审计正常，历史缺失不补造。

### 5.2 环境事实备忘

- seed 网关为 HTTPS 18443（http 空响应），须 `curl -sk`；登录字段为 `loginName`（非 username）。
- member_card 卡项列名为 `card_item`（非 card_type）；audit_log.payload 查询截断须 `payload::text`。
