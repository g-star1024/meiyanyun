## 1. 两卡方案要点

### 1.1 卡A 手工建随访端点 + 随访工作台整页接真（commit `3825a48` + `4492da4` + fix `d130dfc`）

B30 只交付 SOP 自动排程与 complete/skip 写动作，普通（非术后）回访无法手工登记、随访列表整页仍为 mock。本卡补齐：

- **`POST /api/txn/followup`（followup:create）手工建普通随访**（[FollowupService.create](file:///Users/huluobo/WorkBuddy/2026-08-15-23-51-02/meiyun-platform/backend/txn-service/src/main/java/com/meiyun/txn/FollowupService.java)）：
  - 门店强制取 JWT 上下文，**不信入参 storeCode**（门店数据域铁律）；客户经 customer-service `names.customerNames` 解析存在性，不存在返回中文 400 引导先建档（服务间走 HTTP，不跨库直读）；
  - `planDate` 不得早于 `serviceDate`（中文 422 校验）；method 白名单（PHONE/WECHAT/SMS/ONSITE/OTHER），缺省 PHONE；project 截断 128、relatedOrderNo 截断 32，订单号**不反查**（弱关联，沿用 B30 边界）；
  - `sopStage=MANUAL` 与 SOP 节点区分；FU 单号查库号池；审计 FOLLOWUP/CREATE 落 JSON payload。
- **stats 九键**：sopPending/sopOverdue（B30 工作台旧两键语义不动）+ pending/todayPending/overdue/done/skipped + avgSatisfaction（CriteriaBuilder AVG，`setScale(1, HALF_UP)` 一位小数，无记录返回 0）+ adverseCount；**固定 LinkedHashMap 九键顺序**，契约稳定。
- **列表 keyword 模糊 + 真分页**：keyword 对 `lower(customerName)` / `lower(project)` / `coalesce(relatedOrderNo,'')` 做 OR LIKE；过滤项 status/customerId/sopBatchId/sopOnly；固定排序 `plan_date asc, id asc`（不接收前端任意排序字段，防排序注入）；Page 默认 size=20。
- **随访工作台整页 FollowupView 接真**：CPagination 真分页（1 起页码，末页删完自动回退上一页）、关键字 350ms 防抖、三 tab（待回访/已回访/无需回访）stats 角标、四 KPI（待回访/今日待回访/平均满意度 ★/不良反应跟进）、超期 warnbar（最早超期文案取首页首条）、新建回访弹层**真实客户检索选择器（拒收自由姓名）**、完成回访（满意度/恢复情况/不良反应/需复诊）与免回访（原因必填）写动作，全部 v-perm（followup:create/edit）门控。
- **流水牌 BoardView「待回访」列走真库**：mock `sopPending` 改真实 `sopTodos`（`onMounted` 调 `loadSopTodos(auth.user.storeId)`）；`schedulePostOpSop` 降为 **async 空 shim**——术后 SOP 排程只由后端 treat-done AFTER_COMMIT 一条链路负责，防前端与后端 FollowupScheduler 重复排程，并删除前端假 followupId 节点。
- **C 端演示种子保留**：stores/followup.ts 内「陈美玲」2 条 C 端 /m/followup 演示种子与 submitByCustomer 不动（C 端演示栈，B16 既有口径），与真实 API 适配层在同一 store 内共存。
- **fix `d130dfc`（运行态真实缺陷）**：空库（无 DONE 随访）时 `avgSatisfaction` 的 `getResultStream().findFirst()` 遇到 JPA 对 AVG 聚合返回的单元素 null，流内部 `requireNonNull` 抛 NPE 致 `GET /stats` **500**。聚合查询保证单行、AVG 无数据行时该行值本就是 null，改为 `getSingleResult()` 正常返回 null → 接口落 0。独立 fix commit。

### 1.2 卡B SOP 模板编排 + 批次执行整页（commit `70d2b3e` + `53901f6`）

B30 的 SOP 模板只有播种数据、门店无法自助调整节点，批次也无任何执行视图。本卡补齐模板五动作 + 批次聚合读模型 + 一键升级，并把 DueJob 的升级逻辑抽为共享组件：

- **模板节点五动作**（[FollowupSopController](file:///Users/huluobo/WorkBuddy/2026-08-15-23-51-02/meiyun-platform/backend/txn-service/src/main/java/com/meiyun/txn/FollowupSopController.java) 九端点，读 followup:view / 写 followup:edit，字面路径段优先于 `/{id}` 匹配）：
  - 新增节点（stage=MANUAL；label 必填、dayOffset 0–365、method 白名单；落库后按 (dayOffset, id) 全量 renumber lineNo）；
  - 更新节点（内置与自定义均可改 label/dayOffset/method，仅非空字段生效，改后同样 renumber）；
  - 启停 toggle（停用节点**不参与新批次**排程，历史批次/随访不变；空体默认启用）；
  - 删除（**仅 MANUAL 自定义节点可删**，内置节点中文 400「内置节点不可删除，可停用该节点（停用后不再生成新批次）」）；
  - 恢复默认（模板与内置默认同构则短路幂等；否则 deleteByTemplateNo + flush + 按 FollowupSopDefaults 重建内置四节点且全部启用）；
  - `GET /template` 返回含停用节点、lineNo 升序；未播种环境由 `ensureDefaultTemplate` 幂等懒初始化。
- **批次执行看板**：`GET /batches` 分页（keyword 模糊客户/项目/批次号），门店域 storeSpec 显式他店码 404；排序未完结在前 + 服务日倒序；每批内嵌节点 FollowupView 24 字段读模型 + total/done/overdue/finished 聚合。
- **summary 五键**：activeBatches / finishedBatches / sopPending / sopOverdue / needEscalation（未升级超期数），支撑整页四 KPI + warnbar 升级引导。
- **一键升级 `POST /escalate`**：返回 `{"escalated":N}`，把全部未升级超期节点经升级器处理；前端升级后静默刷新 batches+summary（不弹打扰式提示）。
- **FollowupSopEscalator 抽取复用**：B30 的升级逻辑内联在 FollowupSopDueJob 中，本卡抽为 95 行共享组件，60s Job（initialDelay 25s、批 50 FIFO、单条 try-catch 无方法级事务、业务时区 +8）与手动一键升级共用同一条升级链路——置 escalated=true（一次）、本店 STORE_MGR 落 FOLLOWUP/URGENT 站内信（幂等键 `SOP-ESC:{followupNo}:{staffId}`，关 FOLLOWUP 订阅免打扰，org 不可用软降级下轮自愈）；并修复 escalate 后**补 save(f)** 防升级标记丢失。
- **FollowupScheduler 收敛**：删除类内硬编码 DEFAULT_NODES，改读模板**启用中**节点，异常时回退 FollowupSopDefaults.NODES（CARE_24H/1、FOLLOWUP_3D/3、RECOVERY_7D/7、REVISIT_30D/30）；门店停用节点即刻影响后续排程。
- **SopManagementView 整页双 tab 接真**：批次执行看板（四 KPI：进行中批次/待回访/超期/已完结）+ SOP 模板编排（启用/总节点计数、节点行 checkbox 直接 toggle、自定义节点增删改、恢复默认）；warnbar 在 `needEscalation>0` 时出现并带「一键升级」（v-perm.disable followup:edit），升级后切换 infobar「已有 N 个超期节点升级至主管 / 医生」+ 节点「超期已升级」徽标；批次关键字 300ms 防抖；提示文案明确三边界（调整仅影响此后新批次、内置 4 节点可停用不可删、自定义可删）。
