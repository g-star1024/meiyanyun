## 五、问题与教训

### 5.1 缺陷：门店角色可越权写集团模板（数据域漏洞，E2E R9 拦截）

- **现象**：店长 SE001（SST01）编辑/上下架集团模板行（store_code 空串）返回 **200** 而非 404——门店账号竟能改集团通用卡项。
- **根因**：`CatalogService.mustFindInStore` 沿用了**读域可见性**判定 `sc.isEmpty() || rowSc.isEmpty() || rowSc.equals(sc)`，其中 `rowSc.isEmpty()` 表示「集团行对所有门店可见」——这对**读**正确（门店要看得到集团模板才能卖），但对**写**是越权放行：门店角色据此可写集团行。
- **修复**：写操作收紧为 `sc.isEmpty() || rowSc.equals(sc)`（删除 `rowSc.isEmpty()` 子句）——高权限 sc="" 可写一切；门店角色 sc="SST01" 写集团行 rowSc="" 时 `"".equals("SST01")`=false → 404「商品不存在或无权操作」；写本店行 rowSc="SST01" 通过。读路径 listCatalog 仍保留集团+本店合并可见。
- **复测**：重部署 seed 后 R9/R9b（店长动集团行）→ **404**；R9c/R9d（店长写本店卡 CD-005）→ **200**，回读 sessions=6/990 元/OFF_SHELF/includes 全对。修复 jar 以 --skip-build 同步 prod。
- **教训**：**读域可见性 ≠ 写域可改性**。集团/共享数据对下级「可见可引用」但绝不可「越权改」；读写共用一个 mustFind 判定时，必须按操作语义分别收紧。验收须含「下级账号尝试改上级数据 → 403/404」的反向用例。

### 5.2 缺陷：前端 submitForm 同步使用 async store 动作（pnpm build 拦截）

- **现象**：store 去 mock 后 create/update 改为 async，CatalogView.submitForm 仍同步 `store.create(...)` 后直接取 `.id`，TS2339：Property 'id' does not exist on type 'Promise<CatalogProduct|null>'。
- **修复**：submitForm 改 `async function`，`await store.update(...)`、`const p = await store.create(payload)` 后再 `selectedId.value = p.id`；pnpm build exit 0。

### 5.3 缺陷：种子脚本 DDL/TRUNCATE 两处追加丢失（提交前核查拦截）

- **现象**：提交前 `git diff scripts/setup-seed-db.sh` 仅 1 行（sanity），grep 确认 catalog_product 的 CREATE TABLE 与 TRUNCATE 清单两处未落盘（仅 sanity 行在）。
- **修复**：补齐 DDL（表 + uk_catalog_store_code + idx_catalog_product_store，紧跟 store_price DDL）与 TRUNCATE 清单追加，`bash -n` 通过、grep 复核四处（DDL/索引/TRUNCATE/sanity）齐全。
- **教训**：脚本多处追加不能只凭记忆，提交前以 `git diff`/grep 逐处复核落点。

### 5.4 环境与工具备忘

1. shell 代理拦截 localhost：curl 须 `--noproxy '*'`，网关 `-sk https://127.0.0.1:18443`。
2. 无 admin 账号；高权限测试账号 E014（蒋IT SUPER_ADMIN，store_code 空），门店账号 SE001（许店长 SST01）。
3. audit_log.payload 为 jsonb，不能 `left(payload,n)`，须 `payload::text`。
4. 中文 keyword 直接拼 URL 会致 curl 拿到非 JSON；改为拉全量后在客户端按字段过滤。
5. Chrome DevTools MCP：wait_for 的 text 参数为**数组**；take_screenshot 的 filePath 受 workspace roots 限制（/tmp、docs 均被拒），不带 filePath 时截图内联返回。
6. Hibernate 启动在新表上建约束偶现 `constraint ... does not exist, skipping` WARN，为 ddl-auto 正常提示，无害。
