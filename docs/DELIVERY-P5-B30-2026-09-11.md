### 1.3 卡② 建档实时写 ES（commit `09f590b`）

B27 实证新建客户不进 `meiyun-customer` ES 索引（仅靠搜索时 DB 缓存融合兜底）。本卡补齐 outbox 中继实时同步：

- **outbox 表 `customer_search_event`**：建档同事务写 PENDING 事件（只存 customerId，载荷实时从主表读，避免事件体与主表漂移）；
- **中继 Job `CustomerSearchEventRelayJob`**：`@Scheduled(fixedDelay=10s, initialDelay=15s)`，每轮取最早 50 条 PENDING（FIFO 限批），upsert 进 ES：
  - ES 2xx（含重复覆盖）→ SENT，记 sent_at、清 last_error；
  - 连接失败/5xx/429/熔断开路/索引未就绪 → RETRY：retry_count++、记 last_error、log.warn，留 PENDING 下轮补偿；
  - 4xx 确定性拒绝（非 429，如 mapping 拒绝）→ DEAD 待人工，不空转重试；
- **显式 mapping**：启动就绪后幂等确保索引存在，name 中文标准分词 + keyword 子字段，其余过滤/精确字段 keyword；索引已存在不强改 mapping（避免与存量动态 mapping 冲突）；全新索引首次创建时全量回填；
- **熔断降级**：ES 连续失败 3 次开路 30 秒（FAILURE_THRESHOLD=3 / OPEN_MILLIS=30s），开路期间读请求降级 DB、写事件留 PENDING；
- **读时合并 `mergeRecentFromDb`**：ES 召回 id 集后，对查询词补查近期 DB 客户合并（覆盖「刚建档、中继尚未投递」的秒级窗口），再交 DataScope.canReadOwned 做权限过滤；
- 客户搜索主路径不变：ES 取 id → PG findAllById → DataScope 读时合并过滤。

### 1.4 卡① 术后随访 SOP 引擎（commit `40a35ad` + fix `fa549d5`）

工作台「术后待回访」「SOP 超期」两个演示计数依赖此后端域，本卡落最小可用引擎：

- **四张表**（JPA ddl-auto=update 自动建）：
  - `followup_sop_template` / `followup_sop_template_node`：SOP 编排模板与节点（集团通用 store_code=NULL，可停用）；
  - `followup_sop_batch`：每次治疗完成排程出的随访批次（source_plan_id 唯一约束幂等，batch_no 查库号池 `SOP{yyyyMMdd}-{6位序号}`）；
  - `followup`：随访单（FU 单号，sop_batch_id 非空表示术后 SOP 节点，节点共享批次号；plan_date/method/status/escalated 等）。
- **治疗完成自动排程（FollowupScheduler）**：`ConsultPlanService.treatDone` 事务提交后 AFTER_COMMIT 回调触发；按启用模板的节点（默认内置 1/3/7/30 天：术后24h关怀 WECHAT、第3天回访 PHONE、第7天恢复评估 WECHAT、第30天复诊提醒 PHONE）建批次 + 节点；幂等双保险：source_plan_id 唯一约束 + exists 查库；无可用节点不建批次。
- **fix `fa549d5`（运行态真实缺陷）**：afterCommit 回调时原事务已结束，save 无活动事务上下文导致批次/节点**静默丢写**。改为编程式 `TransactionTemplate(PROPAGATION_REQUIRES_NEW)` 显式开物理事务（幂等检查置于新事务内，确保可见已提交数据）。
- **超期升级 Job（FollowupSopDueJob）**：`@Scheduled(fixedDelay=60s, initialDelay=25s)`，范式复刻 ApprovalSlaJob——扫 PENDING + SOP 节点 + plan_date 早于今日零点（业务时区 +8）+ 未升级，限批 50 FIFO，单条 try-catch 不加方法级事务；置 escalated=true（只升级一次）并向本店 STORE_MGR 落 FOLLOWUP/URGENT 站内信，通知幂等键 `SOP-ESC:{followupNo}:{staffId}`，收件人关闭 FOLLOWUP 类别订阅则免打扰；org 服务不可用时软降级（只置标记，下轮自愈补通知）。
- **端点 `/api/txn/followup`**（经既有 txn 网关路由，网关零改动）：
  - `GET /api/txn/followup`（followup:view）：分页 + status/customerId/sopBatchId/sopOnly 过滤；
  - `GET /api/txn/followup/stats`：返回 sopPending/sopOverdue，供工作台两卡真实计数；
  - `GET /api/txn/followup/{id}`；
  - `POST /api/txn/followup/{id}/complete`（followup:edit）：登记回访结果（满意度/恢复情况/不良反应/需复诊等），PENDING→DONE，审计 FOLLOWUP/COMPLETE；
  - `POST /api/txn/followup/{id}/skip`（followup:edit）：标记无需回访，原因 @NotBlank 中文 400，PENDING→SKIPPED，审计 FOLLOWUP/SKIP。
- **工作台切真**：MyWorkbenchView「术后待回访」「SOP 超期」摘除「（演示）」标注，两卡改调 `/stats` 真实端点（auth.can 门控 + 独立容错），计入 todoTotal；仅剩「复诊提醒」1 项演示（依赖营销自动化 Flow，远期）。
