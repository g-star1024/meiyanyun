## 1. 背景与目标

1. **命中不留痕**——拦截发生在 LLM 调用之前，不写 ai_invoke_log（不占配额、不产生 token/费用是对的），但命中事件本身**没有任何落库**，治理台无法审计拦截了谁、命中了哪个词、上下文是什么；

## 5. 真验过程发现与修复

### 5.1 前端静态镜像必须 build 重建（环境坑，非代码缺陷）

8080 前端是**静态 nginx 镜像、无源码挂载**，改 .vue/.ts 后仅 `up -d` 不生效。本卡统一执行 `docker compose -f docker-compose.app.yml build frontend && docker compose -f docker-compose.app.yml up -d frontend` 后再验；后端改 Java/SQL 同样先 `mvn -pl ai-service package` 再 compose build ai-service（V19 经 Flyway 自动迁移并由 PG 实测确认）。

### 5.2 toast 等待超时改以 network 响应判定

标误报/新增等动作的 toast 动画偶发导致自动等待超时，改为以对应 POST 请求响应（200/400）+ 列表回源请求完成为准判定，避免把动画时序误报为功能缺陷。

### 5.3 Chrome MCP 使用经验（本卡新增）

- 过滤下拉每次重开 **uid 会变**（183_x → 186_x），须重新 take_snapshot 取最新 uid；
- evaluate_script 定位动态文案按钮忌猜子串：按钮文案会随选中项变（如「越权提示词（INJECTION）」并不含「词类」），先枚举 `[...document.querySelectorAll('button')].map(b=>b.innerText.trim())` 再用 `startsWith(...)` 精确定位，叶子节点点击用 `[...document.querySelectorAll('*')].find(e=>e.children.length===0 && e.innerText?.trim()==='全部词类')`；
- navigate_page 必须带 url（仅传 ignoreCache 报「Either URL or a type is required.」）。

### 5.4 非本卡缺陷的既有问题（沿用登记，不改动）

- 六功能真实出站在供应商侧偶发 **502**（模型供应商网关旧问题），敏感词拦截发生在其之前，不影响本卡任何验收；
- 其余模块时间展示仍有 slice 硬点（见 §7）。
