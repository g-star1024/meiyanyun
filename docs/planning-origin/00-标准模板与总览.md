## 一、为什么需要本补充

原文档已完成「全量页面树 + 缺口分析 + 逐页一句话说明」，是**规划层**交付。但进入 P3 设计 / P5 开发时，每个页面仍缺：

1. **页面结构**——屏幕的骨架分区与栅格，设计师照此落位即可，无需重新构图。
2. **核心功能分类**——明确本页是「筛选主导 / 表单主导 / 列表主导 / 图表主导 / 流程主导」，避免功能堆叠。
3. **实现方式**——哪些复用样板组件、哪些调用双签模态、哪些落审计日志、Token 如何分配。
4. **交互功能**——钻取、抽屉、弹层、实时校验、批量等具体交互。
5. **页面联动**——上游数据从哪来、下游动作到哪去、横切模块如何串联（这是 SaaS 打通的关键）。

本补充即把原文档的 121 个未产页 + 28 个已产页，全部改写为 7 要素详设。

## 三、设计基线速查（写入④实现方式时必须遵守）

### 3.1 双端金标准骨架

- **桌面 1280×800**：`壳=HORIZONTAL` → 侧栏 `240`（`#14152B`） + 主区 `1040`（`VERTICAL`）。
  - 主区 = 顶栏 `64`（白底，padding `[0,24,0,24]`）+ 内容 `736`（浅灰 `#F6F7FA`，padding `[20,20,20,20]`，`layoutGrow:1`）+ 底栏 `72`（白底，padding `[0,24,0,24]`）。
  - 主区内容：可选「顶栏面包屑 + KPI 4列 + 双栏主体（左主 / 右辅）」。卡片圆角 `12` + 描边 `#EBEBF2`，卡片间距 `12~16`。
- **平板 834×1112**：`壳=VERTICAL`，`counterAxisAlignItems:CENTER`，圆角 `24`，`clipsContent:true`，底色 `#F4F5FA`。
  - 顶部导航 `60`（白底，padding `[0,0,0,16]`）+ 内容流（padding `[16,16,16,16]`，`layoutGrow:1`，可滚动）+ 底部通栏 CTA / FAB（`200×52` 圆角 `26` `#FF6B9D`，`layoutAlign:STRETCH` + 前置 `Spacer` 推底）。

### 3.2 设计 Token（强制使用，禁止自造色）

| 用途 | 色值 |
|---|---|
| 品牌粉（主 CTA / FAB / 警告） | `#FF6B9D` |
| 品牌蓝（链接 / 导航高亮） | `#6B8AFF` |
| 品牌金（评分 / 星级） | `#FFCB47` |
| 品牌青（成功 / 已消解） | `#2ED4BF` |
| 品牌紫（AI / 远期） | `#8B5CF6` |
| 深字 / 灰字 / 浅灰字 | `#1A1A2E` / `#8A8AA1` / `#3A3A4A` |
| 侧栏底 / 墙底 | `#14152B` / `#0B0C1E` |
| 卡片描边 / 主区底 | `#EBEBF2` / `#F6F7FA` |
| 品牌 tint 底（磁贴） | 绿`#E8F5F0` 蓝`#EBF0FF` 紫`#F1ECFF` 黄`#FFF0DB` |

字体：`Sarasa Gothic SC`（中文），标题 Bold / 正文 Regular。KPI 数字 24 Bold / 标签 11 Regular 灰。

### 3.3 合规红线（写入④/⑦时必须显式声明）

- **划扣双签**：涉及钱 / 药 / 客诉 / 退卡 / 资产转移 / 报损的写操作，一律调用 **M4-14 双签确认模态**（双人双签 + 账实一致校验），禁止单人提交。
- **EMR 不可篡改**：电子病历（M4-17）只读 + 更正留痕，禁止就地修改历史。
- **审计 append-only**：所有敏感操作写 `T1-04` 操作审计（仅追加，不可改删）。
- **敏感词拦截**：咨询 / 话术 / 推送文案经 `A1-04` 实时拦截。
- **等保三级 / 字段级 RBAC**：页面数据范围受角色 + 组织树（`M1-05` / `T1`）约束，跨店数据隔离。
- **绝不碰资金池**：财务仅做镜像 + 对账（金蝶/用友单向镜像 + Outbox + T+1 三方对账 + `transaction_id` 幂等），不直接收付款。

## 六、使用约定

- 设计师：照 ① 结构 + ④ 实现方式落位，提交前跑 `设计铁律.md` 第五节「新增屏幕检查清单」。
- 开发：照 ③ 核心功能分类定组件，照 ④/⑦ 落双签、审计、RBAC、联动接口。
- 评审：以 ⑥ 达成效果为验收口径，以 ⑦ 页面联动验证闭环完整性。
