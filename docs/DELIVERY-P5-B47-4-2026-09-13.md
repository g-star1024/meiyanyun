## 1. 背景与目标

AI 经营日报页按「四 KPI + 环比 + 日报摘要与建议 + 历史期次 + 订阅」组织门店日常经营复盘能力，卡4 之前整页是硬编码 mock：KPI/环比写死、日报摘要与建议写死、「生成日报」只回填本地假内容、「采纳为任务」无后端动作、订阅开关纯本地态、渠道推送区为假入口。

与卡2/卡3 的**逐客户串行批次**不同，日报是**按日期单用户视角的单次生成**：一次出站调用产出整篇结构化报告（摘要 + 5 条建议），事实输入（当日营收/到店/新客/异常/退款及环比基线）主要在**交易域**，本卡打通 ai→txn 一条跨服务只读富化，远程失败降级为 available=false 不阻断页面（KPI 显「—」而非假数）。同日允许重发生成**新版本报告**（新 report_id + 新建议集 + 新 invoke log），历史按 date|store 归并展示最新版，旧版本 append-only 留档可审计。

B47 卡4 验收口径：

1. 选定日期真实调用火山方舟 ark-code-latest 生成结构化日报（摘要 + core/anomaly/action 三类建议），报告与建议落新表并与 ai_invoke_log 同源关联；
2. 复用既有 invoke **全治理链**（功能启用/角色灰度矩阵/门店灰度/敏感词/配额/模型校验/计费/ai_invoke_log），不平行造一套出站；
3. 四 KPI（营收/到店/新客/异常数）与环比口径全部真实取数，跨服务不可用时 available=false 诚实置「—」，不伪造；
4. 历史期次真实分页读取、选期联动 KPI 与报告；当日无报告显诚实引导空态（GET report 404 前端静默转空态）；
5. 「采纳为任务」幂等置位（重复采纳 changed=false 不重复写审计）、订阅开关幂等（SUBSCRIBE/UNSUBSCRIBE 审计）；
6. 四个推送渠道（站内/短信/企微/公众号）在 M5-03 真实触达建成前全部 disabled 诚实置灰并标注，不伪造入口；
7. 页面样式主体零改动，长耗时生成期间按钮置灰防重复提交。

## 5. 真验过程发现与修复

1. **日报「生成时间」差 8 小时（真实缺陷，已修复）**：Chrome 首屏历史生成时间显示 09:14:50（UTC），应为北京 17:14:50。根因：PG `timestamptz` 经 JPA 映射为 **UTC 偏移的 OffsetDateTime**，DailyService 两处直接 `r.getCreatedAt().toLocalTime().format(TIME_FMT)` 取了 UTC 墙钟。修复：新增私有 `bjTime(OffsetDateTime)` = `t.withOffsetSameInstant(ZoneOffset.ofHours(8)).toLocalTime().format(TIME_FMT)`（null 安全返空串），替换 history 映射与 toReportView 两处；重打包（期间一次 SearchReplace 多括号致编译错误 [520,79]，`)))`→`));` 修复）→重建 ai-service→force-recreate healthy，curl 与 Chrome 双验显 17:14:50。教训：全站 timestamptz 展示均需显式时区转换，B46 卡1 的前端 datetime.ts 工具覆盖浏览器侧，本卡后端直拼时间字符串场景须在服务端转 +08:00。
2. **daily/generate 首测 504——nginx 60s 默认代理超时截断真实长出站（真实链路缺陷，已修复）**：真实 ark-code-latest 日报生成实测 86.9s（首版 4523 tokens）与 118.0s（重发 5801 tokens），后端 LLM 读超时与前端 axios 均 180s，但前端 nginx 反代 `proxy_read_timeout` 为默认 60s，提前回 504（后端仍成功落库）。排查确认真实网关是仓库根 `gateway/` 的 **Go 项目**（net/http + httputil.ReverseProxy，http.Serve 无任何超时配置，不截断），backend/gateway（Spring Cloud Gateway）目录不存在，瓶颈仅在 nginx。修复：nginx.conf 增加正则 location `~ ^/api/ai/(daily/generate|churn/run)$`（一并覆盖卡3 churn/run 同类隐患），proxy_connect 10s、send/read 180s，置于通用 `/api/` 前缀块前（正则优先），重建 frontend 镜像后重发生成 HTTP 200/118s 端到端打通。教训：长耗时 LLM 路由的超时必须在「前端 axios / nginx / gateway / 后端 RestClient」四跳同时对齐，任一跳默认值都会成为隐性瓶颈。
3. **docker exec heredoc 无回显（工具用法）**：未加 `-i` 时 SQL 实际已执行但无输出，加 `docker exec -i` 后正常；PG 用户为 meiyun（非 postgres）、库 meiyun_core。
