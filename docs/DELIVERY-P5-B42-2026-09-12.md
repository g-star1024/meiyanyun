## 2. 数据模型（V15 七表）

| 表 | 用途 | 要点 |
|---|---|---|
| `ai_provider` | 供应商 | provider_code 唯一；`api_key_cipher`（AES-GCM Base64 密文）+ `api_key_mask`（掩码回显）；protocol 默认 OPENAI；enabled 默认 false（上线须审批，禁自动生效） |
| `ai_model` | 供应商下模型登记 | (provider_id, model_code) 唯一；能力集 capabilities 逗号分隔 CHAT/EMBEDDING/VISION；上下文窗/温度/topP/maxTokens/优先级；conn_status SUCCESS/FAIL/UNKNOWN 三态+conn_message+conn_checked_at；input/output 单价（元/百万 token，空=不参与计费） |
| `ai_feature_binding` | AI 功能→模型绑定 | feature_code 唯一；门店灰度 store_scope ALL/SPECIFIED + store_codes；prompt_template；param_overrides JSON；require_approval |
| `ai_feature_role` | **功能×角色灰度矩阵** | 复合主键 (feature_code, role_code)；**这是 A1 管理台的功能开放开关，独立于 T1 RBAC 操作权限码**，页面文案已显式注明，二者不可混为一谈 |
| `ai_invoke_log` | 统一调用日志 | 调用人/门店/功能/供应商/模型、入出参各截 500 字、三类 token、latency_ms、success/error_code、cost_fen；时间/功能/门店三索引 |
| `ai_approval` | 上线审批 | 主键 **approval_id**（注意不是 id）；类型 PROVIDER/MODEL/BINDING；PENDING/APPROVED/REJECTED；decided_by/at/opinion |
| `ai_global_cfg` | 全局配置单行 | cfg_id=1 启动幂等插入；默认模型、灰度 0~100 CHECK、留存月数、敏感词/可解释/自动审计三开关 |

`ai_quota`（配额）二期再建，本期不落地。

## 3. 后端能力清单（全部真实端点，类级前缀 /api/ai）

- **供应商** ProviderController：`GET /providers`、`POST /providers`、`GET/PUT /providers/{id}`、`POST /providers/{id}/delete`（软停用删除）；写动作经 ApiKeyCipher AES-GCM 加解密，回读只出掩码与 hasApiKey。
- **模型** ModelController：`GET /models`、`POST /models`、`GET/PUT /models/{id}`、`POST /models/{id}/delete`、**`POST /models/{id}/test` 连通性测试**（LlmClient ping，落 conn 三态+消息+时间）。
- **功能** FeatureController：`GET /features`、`GET /features/{code}`、`POST /features/{code}/binding`（绑定模型/灰度/提示词）、`POST /features/{code}/roles`（灰度矩阵 upsert，稀疏存储 false 也落）。
- **全局配置** GlobalCfgController：`GET/POST /cfg`（GET 附 modelOptions 供下拉；灰度边界校验）。
- **日志/KPI** InvokeLogController：`GET /logs`（功能/成败过滤真分页）、`GET /logs/bill`（月度账单）、**`GET /logs/kpi`（KPI 聚合真实路径是 `/api/ai/logs/kpi`，不是 `/api/ai/kpi`）**。
- **审批** ApprovalController：`GET /approvals`（Spring Page 真分页+状态过滤）、`POST /approvals/{id}/decide`（通过/驳回+意见）。**没有 apply REST 端点**：本期审批单由审批联动/验证产生，申请提交动作属后续批次。

### 安全与四件套

- 服务间调用走网关 internal 通道 + `X-Internal-Token`；写端点权限码：`aiAdmin:edit`（配置类）、**新增 `aiGovern:approve`（审批决策）**。
- **密钥安全**：[ApiKeyCipher.java](file:///Users/huluobo/WorkBuddy/2026-08-15-23-51-02/meiyun-platform/backend/ai-service/src/main/java/com/meiyun/ai/security/ApiKeyCipher.java) AES-GCM，主密钥从 `AI_CONFIG_SECRET` 注入（dev 默认值仅本地联调，compose 透传宿主环境变量）；密文/明文均不进审计 payload 与日志，页面只见掩码。
- 写接口四件套：Bean 校验 + 中文业务错误（GlobalExceptionHandler 统一 400 BUSINESS_ERROR 中文 message，如重复决策「该审批单已处理，当前状态：已驳回」）+ 全动作审计（RestAuditRecorder 转发 audit-service，审计哈希链延续）+ 幂等（重复决策拒绝、审批通过联动模型启用 MODEL_ENABLED、BINDING 驳回 linkage=NONE 绑定保持 disabled）。

### 关键踩坑：api/client.ts 不剥离 .data

前端存在**两套 axios 实例，约定相反**：
- [api/client.ts](file:///Users/huluobo/WorkBuddy/2026-08-15-23-51-02/meiyun-platform/frontend/src/api/client.ts) 响应拦截器是 `(resp) => resp`——**返回完整 AxiosResponse，不剥离 data**。凡 import 它的 API 模块必须 `.then((r) => r.data)`（auth.ts 即此模式；org.ts 则直接返回由消费端自取 .data）。
- 另一套 api/request.ts（service/http）拦截器才是 `return response.data`。

ai.ts 初版 19 个函数全部裸 `return client.get/post(...)`，页面拿到 AxiosResponse 后对数组 `.map` 报运行时 `TypeError: k.value.map is not a function`，表格出 6 行「未配置/停用」空骨架——**接口 200、响应体正确，但页面渲染异常**；vue-tsc 编译期发现不了（裸 axios 调用类型宽松），只有真页面运行才暴露。修复：19 个端点统一补 `.then((r) => r.data)`，npm run build 0 error，重建前端镜像后四页全部正常。**新增任何 import client 的 API 模块，务必逐条带 `.then((r) => r.data)`。**
