# 美研云工作台重构：竞品对标 + 现状诊断 + 重构方案

> 文档版本：2026-08-28
> 适用范围：美研云门店中台前端（`meiyun-platform/frontend`，Vue3 + TS + Pinia + Vite）
> 状态：**方案已全部落地并通过双端核验**（vue-tsc 0 error、vite build 通过、Playwright 桌面 1280 / 平板 834 双端 85 项断言全过、0 console error）。
> 说明：本文重构的是**一线服务作业工作台**（预约→接待→咨询→开单→收银→核销→病历→回访的客户动线），不是 C 端小程序，也不是 M6 财务 / M1 集团治理等管理后台。

---

## 一、竞品对标

### 1.1 对标对象

医美 / 美业 SaaS 一线工作台参考：**宏脉（宏脉客云）、领健 LinkedCare / 领健美业、有赞美业、美团医美 SaaS、新氧云诊所**；横向参考连锁服务行业的预约型 SaaS：**Phorest、Mangomint、Vizitor**（海外美业）、**博恩 / 领健口腔**（口腔连锁，作业流与医美高度同构）、**禾维智美**。

> 注：以下为基于公开产品资料与行业通识的归纳，用于提炼设计范式，不代表对任一产品内部实现的逐字断言。

### 1.2 核心结论：一线作业流与门店运营后台是两套界面

调研确认的最关键分界——主流医美 SaaS 都把「围绕客户在院动线的高频作业」与「围绕门店资源的低频管理」分成两个界面心智：

| 归属 | 内容 | 使用频率 | 使用人 |
|---|---|---|---|
| **一线工作台**（作业流） | 预约看板、接待/到店、咨询面诊、开方开单、收银、划扣核销、电子病历、术后回访、复诊提醒、交接班 | 分钟级、全天挂屏 | 前台、咨询师、医生、收银、护士 |
| **门店运营后台**（管理） | 排班考勤、库存耗材、设备床位、物料申领、报损、员工绩效、价目/卡项定义、报表 | 小时/天级、按需进入 | 店长、库管、运营 |

这直接决定了美研云的导航边界：**交易作业链归「工作台」，资源管理归「门店运营」**。

### 1.3 五个可借鉴的设计范式

1. **全院"流水牌 / 流量看板"作为一线首页**
   宏脉、领健都有一张"在院客户状态板"：客户按当前所处阶段分列（候诊→咨询→收费→治疗→离院/回访），一眼看清全院在忙什么、谁卡住了。美研云落地为 `/board` 全院客户流水牌。

2. **角色待办（My Day / 我的工作台）作为个人首页**
   Phorest、Mangomint 登录后是"今天我要处理什么"的待办清单（我的预约、待收款、待回访、审批），按当前登录角色过滤，而不是一张所有人都一样的功能菜单。美研云落地为 `/my-workbench`。

3. **列表-详情（list-detail）是作业页的统一骨架**
   几乎所有一线作业页（接待、咨询、回访、工单、核销）都是"左侧单据/客户列表 + 右侧处理详情 + 底部主操作"。竞品这一套高度一致，差异只在业务字段。美研云落地为 `CWorkbenchShell` 统一骨架。

4. **作业流要有明确的"下一步"出口**
   咨询完→引导开单；收完款→引导治疗；核销完→引导回访。竞品不会让一线人员在单据终态停下来想"接下来点哪"，而是在完成态直接给出下一环节入口。美研云落地为终态页 `.wbs-foot-done` 完成提示 + 下一环节主按钮。

5. **动作即时反馈、危险动作二次确认**
   写操作（收款、核销、签名、双签）成功后有明确 toast/回执；涉及金额、医疗、合规的动作用弹层二次确认 + 留痕。美研云落地为全局 `useToast` + 双签弹层。

## 二、现状诊断（重构前的问题）

重构前对全站页面、路由、导航、布局做了普查，核心问题五类：

1. **一线作业链被拆散在不同菜单**
   预约、咨询、收银、核销、病历、回访等本应是"一条客户动线"的页面，散落在「交易管理」「门店运营」「病历与交班」等多个分组里，前台/咨询师要跨菜单跳着干活。

2. **缺统一的一线首页**
   登录后默认进预约看板，没有"全院在忙什么"的流水牌，也没有"我今天要处理什么"的个人待办。新人不知道先点哪。

3. **作业页布局各写各的，外壳重复**
   咨询台 `cw__`、医师台 `dw__`、随访 `fu__`、复诊 `rc__`、病历 `emr__`、工单 `wo__`、划扣台 `wd__`、接待 `ci__` 等 **8+ 套类名各自实现了一套"KPI + 左列表 + 右详情 + 底部操作"外壳**，结构雷同、样式漂移、维护成本高。

4. **终态页是"断头路"**
   收款完成、核销完成、病历归档、复诊已预约后，页面停在完成态，没有"下一步去哪"的出口，动线在终点断裂。

5. **反馈机制不统一**
   部分页面用 `window.alert`，部分自绘 `.toast`（固定底部 + 各自动画），观感和行为不一致；DEMO 页（closed-loop）还挂在正式导航里。

## 三、重构方案与落地

### 3.1 信息架构：7 业务域 + 一线/后台两分区

导航（`src/config/nav.ts`）重组为顶部 7 个业务域 Tab：

```
工作台 | 客户运营 | 门店运营 | 营销中心 | 财务 | AI 中心 | 管理后台
```

- **工作台**（一线服务作业动线）分 4 组：
  - 一线首页：全院流水牌 `/board`、我的工作台 `/my-workbench`、客户档案
  - 预约与接待：预约看板、智能排队、接待台、客情登记、到店核销
  - 咨询与诊疗：咨询工作台、医师工作台、项目开方开单、电子病历
  - 收银与核销：收款收银、划扣核销、划扣执行台
  - 术后跟进组：术后回访与满意度、术后 SOP 编排、复诊提醒
  - 协同与概览：经营概览、审批中心、交接班、消息通知
- **门店运营**：商品与价格、门店日常（排班/库存/物料/设备/工单/日报/绩效）、门店管控、门店主数据——**资源管理，不再混入交易作业链**。
- 页面路由 / URL / 权限码全部保留，仅重组菜单分组；域高亮由 `detectDomain` 数据驱动自动生效。

每个业务域配聚合频道首页（`DomainHomeView.vue` + `config/domain-home.ts`）：KPI 概览 + 模块矩阵（按权限自动聚合该域菜单）+ 关键信息 + 待办。

### 3.2 两个一线首页

- **全院客户流水牌 `/board`（`BoardView.vue`）**：按客户在院状态分列（候诊→咨询→审核→收费→治疗→回访），聚合 arrival / consultation / order / followup 现有 store，**不建新状态机**。卡片点击进客户 360；列头"去处理"跳对应作业页。
- **我的工作台 `/my-workbench`（`MyWorkbenchView.vue`）**：我的待办（行内实时计数 → 点击直达作业页）+ 高频操作 + 今日概览。待办用「**权限码 + 实时计数**」驱动，天然按当前角色过滤，无需硬编码角色分支。

### 3.3 统一作业骨架 `CWorkbenchShell`

`src/components/CWorkbenchShell.vue` 收敛 8+ 套重复外壳为一套 `wbs__` 类名：

- Props：`hasSelection / emptyIcon / emptyTitle / emptyDesc / listWidth`
- 插槽：
  - `#kpis` 顶部 KPI 行（统一用 `CKpi` 组件）
  - `#list` 左列卡（sticky，tabs/筛选 + flex 滚动列表）
  - `#head` 详情头（标题 + 状态胶囊，外包 `.wb-head` flex 容器）
  - 默认插槽 详情体（滚动区 `max-height: calc(100vh - 380px)`）
  - `#foot` 底部操作条（按状态机条件渲染）
  - `#empty` 空态（也可用 props 走默认）
- 响应式：≤1100px 自动降单列、KPI 降 2 列。

**迁移范式**：KPI→`#kpis`；tabs/筛选+滚动列表→`#list`；标题+状态→`#head`；详情→默认插槽；操作按钮→`#foot`；空态交骨架 props；弹层（modal-mask）留在骨架外。跨插槽 TS 无法收窄类型时，每个插槽内容外包 `<template v-if="selected">`（运行时恒真，纯类型收窄）。

**已迁移到骨架的 9 个一线作业台**：

| 页面 | 路由 | 原类名 |
|---|---|---|
| 咨询工作台 | `/consultation` | cw__ |
| 医师工作台 | `/doctor` | dw__ |
| 术后回访与满意度 | `/followup` | fu__ |
| 复诊提醒管理 | `/recall` | rc__ |
| 电子病历管理 | `/emr` | emr__ |
| 到店核销（接待台） | `/m2-checkin` | ci__ |
| 服务工单 | `/m2-workorder` | wo__ |
| 划扣执行台 | `/m2-writeoff-desk` | wd__ |
| 划扣核销（收银侧） | `/writeoff` | wo__ |

> **评估后保留不迁移**（非 list-detail 作业台，强行套骨架破坏信息密度）：
> - `FinWriteoffView`（`/m6-writeoff` 划扣明细）：财务只读镜像，带收入确认口径规则条 + 双签轨迹；
> - `FinReconcileView`（M6 对账中心）：T+1 三方对账、8 大恒等式多面板、一键轧平/人工调平。

### 3.4 终态页"下一步"出口

每条动线终点补"下一步"，统一用 `.wbs-foot-done`（绿色 inline-flex 完成提示，靠左）+ 主按钮导向下一环节：

- 医师台治疗完成 → 术后 SOP 进度 / 电子病历 / 客户 360·跟进复诊
- 收银台收款完成 → 诊疗单"已解锁治疗·前往治疗"（深链 `/doctor?fromConsult=`），零售单"前往核销"
- 接待核销完成 → 进入咨询工作台
- 复诊已预约 → 前往预约看板
- 病历归档 → 新建修订
- 随访完成 → 转客户档案 / 复诊提醒 / 客户 360
- 工单 / 划扣台完成 → 完成提示条

> `/writeoff` 核销执行台是持续作业台（核销后单据即离开待核销列表），foot 恒为"确认核销"，无终态条，属设计合理。

### 3.5 全局反馈与清理

- 新增全局 toast：`src/composables/useToast.ts` + `src/components/CToastHost.vue`（模块级单例，success/error/info/warning），替换所有 `window.alert` 与 WriteoffView 自绘 `.toast`。
- 删除死代码（`src/_legacy_views`、`_legacy_components`、`_legacy_api`），`/closed-loop` DEMO 移出正式导航。
