## 一、本批目标与边界

### 1.1 立项决策（B7 §七 余下列项中为何只自主开工报表导出）

B7 移交四项：① 非现金渠道账实接入；② 财务运维报表导出；③ 月结成本结转自动化；另 DESIGN 决策点 #4（咨询师提成自动化）、#5（BOM 自动扣耗材）悬置。逐项判定：

1. **非现金渠道账实接入**：依赖微信/支付宝/银行回单等**外部商户数据源**，当前环境无任何商户号/对账单接口可接；自主开工必然编造外部数字，违反诚实降级红线⑤。**不自主开工**，待外部凭据。
2. **财务运维报表导出（本批）**：纯只读，复用 B5/B7 已验证的真实聚合（settlementService.list / tripartiteService.tripartite / aggregation.ledger / cost_allocation 聚合），无外部依赖、无写路径、可逆（仅生成文件），可双栈真实验证。**自主开工**。
3. **月结成本结转自动化**：涉及跨月成本自动结转的会计口径与不可逆账务动作，属会计政策选择，须用户拍板结转规则（按什么动因摊、差异如何处理）。**不自主开工**。
4. **提成自动化（决策点 #4）/ BOM 自动扣耗材（决策点 #5）**：DESIGN 明示为决策点，涉薪酬规则与库存自动扣减，**不自主开工**。

### 1.2 目标

四个只读 CSV 导出端点（GET，类级 `finance:view`；封账台账沿用 `finance:settlement:view`）：

| 端点 | 数据源（复用既有聚合，零新查询口径） | 表头列数 |
| --- | --- | --- |
| `GET /api/finance/export/settlement.csv` | settlementService.list(periodType, periodKey, storeCode) | 11 列：封账单号/期间类型/期间/门店编码/门店名称/状态/分录笔数/净额(元)/备注/封账人/封账时间 |
| `GET /api/finance/export/tripartite.csv` | tripartiteService.tripartite(date, storeCode)，取 stores 明细行 | 17 列：对账日期/门店编码/门店名称/经营净额/落账净额/账账差异/人工成本/未解释差异/现金交接/现金差异/现金票数/订单数/退款数/划扣对数/退卡数/落账分录数/是否核对通过 |
| `GET /api/finance/export/ledger.csv` | aggregation.ledger(storeCode, from, to) | 12 列：分录号/日期/门店名称/科目/方向/金额(元)/渠道/来源/业务单号/对账状态/摘要/发生时间 |
| `GET /api/finance/export/cost.csv` | cost_allocation 聚合（口径逐字复制 FinanceController.cost：DataScope.storeSpec + month withDayOfMonth(1) + 按 periodMonth|storeCode 归并四类成本 + resolveStoreNames 补店名） | 8 列：月份/门店编码/门店名称/耗材成本/报损成本/折旧成本/人工成本/合计（元） |

CSV 统一约定：UTF-8 **BOM（EF BB BF，Excel 中文不乱码）**、中文表头、CRLF 行尾、RFC4180 转义（含逗号/引号/换行字段双引号包裹）、金额 Long 分 → 元 `/100.0` 两位小数（Locale.ROOT，避免逗号小数点）、文件名 `中文报表名[-条件]-yyyyMMdd-HHmmss.csv`、响应头 `Content-Disposition: attachment; filename="export.csv"; filename*=UTF-8''<URLEncoder 中文名>`。

### 1.3 边界红线（本批不碰）

- 纯只读导出：**零新增写端点、零 DDL、零表结构变更、零网关改动**；不改任何既有聚合口径，导出服务是既有 JSON 接口的「薄翻译层」。
- 不做 Excel/PDF、不做异步大数据量导出、不做报表定时邮件——当前数据量（千行级）同步导出足够。
- 不新增 `finance:export` 后端权限点（见 §5.3 现状说明）。

- **新增 `FinanceExportService.java`**（258 行，@Service）：

### 2.2 前端（零样式改动，仅接线）

- `src/api/finance.ts`：新增 4 个导出 API（`exportSettlementCsv / exportTripartiteCsv / exportLedgerCsv / exportCostCsv`），axios `responseType: 'blob'`；内部 `downloadCsv(resp, fallback)`——优先从 `Content-Disposition` 的 `filename*=UTF-8''` 解析后端中文名（decodeURIComponent，失败回落原串），创建 Blob → 临时 `<a download>` 点击 → 撤销 ObjectURL。
- 四个页面按钮均为**既有按钮**，仅把点击行为从「本地拼 CSV / mock」改为「后端优先 + 本地回落」：
  - `FinSettlementView.vue`：「导出 CSV」按当前筛选（periodType/periodKey/storeCode）组参调 `exportSettlementCsv`。
  - `FinReconcileView.vue`：三方对账 tab「导出门店明细 CSV」按 date/store 组参调 `exportTripartiteCsv`；outbox tab 既有 `exportReport` 原样保留。
  - `FinLedgerView.vue`：「导出流水」`try { await exportLedgerCsv(); return } catch { /* 回落本地明细 CSV */ }`。
  - `FinCostView.vue`：「导出」`try { await exportCostCsv(); return } catch { /* 回落本地明细 */ }`，**无参调用**（不传 month）。
- **回落策略说明**：ledger/cost 两页原本就有「前端按当前加载数据拼本地 CSV」的降级逻辑；本批改为后端 API 优先、失败时 catch 回落原本地导出——后端可用时导出的是全量/服务端口径，后端不可用时用户仍能导出当前页所见数据，按钮永不因接口异常而无响应。settlement/tripartite 两页无本地回落（数据本就来自后端，导出失败直接抛错由全局提示）。
- 构建：`npx vue-tsc --noEmit` 退出码 0（downloadCsv 的 headers 参数为兼容 Axios 响应头类型定为 `unknown` 内部收窄）；`pnpm build` ✓ built（产物 index-eEorxRaX.js）。

## 六、问题与教训（归档必录）

### 6.1 cost 导出 month 参数格式 500（测试参数错误，非 B8 代码 bug）

- 现象：curl 测 `cost.csv?month=2026-08` → 500，日志 `DateTimeParseException: Text '2026-08' could not be parsed at index 7`（FinanceController.java:154）。
- 定性：B5 既有契约——cost 接口 month 参数为 `yyyy-MM-01`（`LocalDate.parse(month).withDayOfMonth(1)`），传 `yyyy-MM` 必然解析失败。B8 导出端点沿用同一契约。
- 用户路径不受影响：grep 确认前端 `exportCostCsv()` 与 finCost store `getCosts()` 均**无参调用**（不传 month，导出全部可见月份），前端永不触发该 500。
- 处理：**未改代码**（改契约属 B5 接口变更，不在本批范围；且 yyyy-MM-01 契约本身自洽）。测试改用 `month=2026-08-01` 后 JSON/CSV 均正常。

### 6.2 环境/工具事实备忘

- tripartite 接口返回**裸对象**（顶层 date/stores/flowCounts…，非 `{data}` 包裹）；ledger 接口返回**裸数组**——curl 管道 python 解析时需分别按 dict/list 处理。
- Chrome DevTools MCP：`navigate_page` 参数名是 **pageId**（非 page）；`list_network_requests` 不支持 urlContains/limit，用 `pageSize` + `resourceTypes:["xhr","fetch"]`。
- 财务前端路由前缀为 **/m6-**（/m6-ledger、/m6-reconcile、/m6-settlement、/m6-cost），/fin-* 为 404。

### 6.3 finance:export 权限点现状（如实记录，不在本批扩权）

- 四个导出按钮在前端均以 `finance:export` 权限码做展示守卫（B5 既有按钮的既有守卫）；但**后端不存在 `finance:export` 权限点**——导出端点实际鉴权为类级 `finance:view`（settlement 为 `finance:settlement:view`），即「能看页面就能导出所见数据」，对只读报表而言口径自洽（导出内容不超过页面可见范围，且同样过 DataScope）。
- 本批不新增后端权限点：新增权限点需动权限种子/角色配置，超出「只读导出」批次范围；如后续要求「可看不可导出」的细分管控，再单独立项补 `finance:export` 权限点 + 角色授予。
