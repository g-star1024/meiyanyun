## 一、本批目标与边界

**目标**：把财务台账从 B1/B2 的「读时聚合镜像」升级为「事件驱动落账」——经营域（txn）收款成功、退款终审、划扣完成四个触发点发生资金动作时，写本地 `finance_event` 表（本地 outbox 模式），定时重试任务投递到 finance 内部写端点，finance **幂等**落 `fund_entry` 资金分录（系统账本表），并逐笔登记 `outbox_record` 对账台账；财务在对账中心人工「标记一致 / 标记差异 / 双签调平」，差异调平补一笔调平分录（全审计留痕，不反向动业务账）。读模型与读时聚合 **ledger-diff 双跑校对**，零差异。

**边界（红线）**：

- 跨服务写只走内部端点（`X-Internal-Token` + 内部权限码），不直连别域库；
- 金额后端一律 `Long` 分（`amount>0` 约束，方向由 `direction IN/OUT` 表达），前端元；
- 写接口四件套齐全：入参校验 / idem_key 幂等唯一约束 / 全审计（audit_log 哈希链 + 操作留痕）/ 中文错误消息；
- 调平仅补财务侧调平分录，**绝不反向修改支付/银行/订单任何金额**（弹层红线文案明示）；
- UI 模型 ≠ 后端能力处诚实降级：三方回单（渠道/银行）B6 才接入，本批回单列一律「回单未接入」，长短款不自动判定、不臆造；
- 样式零改动：仅新增/接线真实数据，不调整既有视觉。

**关键口径决策（DESIGN §5.2 方案 a，用户已拍板）**：事件投递 = **本地 outbox + 定时重试 + finance 幂等**（不引 MQ），重试任务固定间隔扫描 PENDING 事件重投，消费端以 idem_key 唯一约束去重，重复投递不双算。

**outbox 状态机 curl 实测（服务端强制，中文错误）**：

- `mark-reconciled`：PENDING→RECONCILED 成功（OB-4、OB-5）；
- DIFF 调 mark-reconciled → 400「当前状态「DIFF」不可对账：仅待对账（PENDING）记录可标记对账结果」；
- PENDING 调 adjust → 400「当前状态「PENDING」不可调平：仅差异（DIFF）记录可执行调平」；
- 合法转移：PENDING→mark-diff→DIFF→adjust→ADJUSTED（adjust 自动生成 ADJUST 子 outbox，对应补录 fund_entry，子记录走 mark-reconciled 收口）。

**ledger-diff 双跑校对**：`GET /api/finance/internal/ledger-diff?from=2026-09-05&to=2026-09-05`（**日期参数须 yyyy-MM-dd，传 ISO datetime 被中文 400 拒**）→ `matched:true`、aggNetFen=postedNetFen=666,000、netDiffFen:0、adjustCount:1/adjustFen:1,200。读时聚合与落账零差异。

## 五、问题与教训（归档必录）

1. **meiyun-security 共享模块须 clean install + 核验 fat jar 内 jar 字节数**：安全模块改后若只 `package` 单服务，依赖的旧 jar 可能被打入；必须根 `mvn clean install`，并核验 fat jar `BOOT-INF/lib/meiyun-security-*.jar` = 新版 24,632 字节。容器内无 unzip，须宿主机核验。
2. **审计哈希链时间戳格式**：须 UTC 微秒截断、小数秒去尾零、`Z` 后缀；纳秒精度会导致链式哈希假性断链。seed 晨间 id 1-11 旧 jar 记录不可复算（brokenAtId:1），新 jar id 12-23 全合法、prod 112 全绿。
3. **Pinia store 异步数据竞态（本批浏览器复验抓出的真实 BUG）**：快照型子 store（useFinAbnormalStore）的 `seed()` 原为**同步**函数，onMounted 时直接 `syncFromCore()` 快照 `core.outbox`；而 financeCore 的台账靠 store 初始化处 `void seed()` **异步** fetch，onMounted 时刻 outbox 仍为 `[]`，快照结果**永久为空**（直达 /m6-abnormal 显示「暂无异常账务」，但 OB-3 实为 DIFF）。对账中心正常是因其 computed **直接读响应式** `fin.outbox`，fetch 完成后自动重渲染。
   - **修复**：子 store seed 改 `async`，`await core.seed()` 确保台账拉取完成后再 `syncFromCore()`（seeding Promise 去重 + force 强制刷新）；视图 `onMounted(() => void store.seed())`；「同步」按钮改 `store.seed(true)`（先强制拉后端再同步），不再调裸 syncFromCore。
   - **同类全站扫结论**：finReports 卡余额 store（自身 async seed）、月报 store（computed 直接读响应式 core.entries）、m5Roi（async seed + computed 消费）、m5Channel（B2 已复验）均**无此竞态**，唯一病灶即异常 store。
   - **规则**：凡「把异步 store 的数据快照进本地 ref」的子 store，必须 await 数据源 seed 完成后再快照；优先用 computed 直接读响应式源，避免一次性快照。
4. **ledger-diff / outbox 日期参数格式**：内部端点日期参数为 `yyyy-MM-dd`（如 `from=2026-09-05`），传 ISO datetime（`2026-09-05T00:00:00Z`）被中文 400 拒。
5. **outbox 状态机转移规则**（服务端强制，勿在前端假设）：PENDING→RECONCILED（mark-reconciled）、PENDING→DIFF（mark-diff）、DIFF→ADJUSTED（adjust）；adjust 自动生成 ADJUST 类型子 outbox（对应补录 fund_entry），子记录走 mark-reconciled 收口；非法转移一律中文 400。
6. **不得打印/物化凭证值**：部署与核验过程中不输出数据库/内部 token 明文；seed 码系（SC*/SST*、SE* 员工）与 prod（M*/ST-SH-*）不同，跨栈复验注意区分。
7. **DB 主键列名以 `\d` 实证为准**：outbox_record 主键是 `outbox_id`、fund_entry 是 `entry_id`（非 `id`），写查询/脚本前先 `\d 表名` 取真实 schema 与 CHECK 约束。
