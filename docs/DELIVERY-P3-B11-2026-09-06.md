# P3-B11 交付：月结成本结转自动化（后台可配结转规则 + 设备台账直线折旧 + 封账前自动结转 + 期间封账不可改账）

- 批次：P3-B11
- 日期：2026-09-06
- 上批：P3-B10（BOM 自动扣耗材，已交付）
- 本批性质：功能开发（finance-service 后端 + 前端两个财务页面域）+ 真实双栈部署验证 + 封账全链路 E2E
- 前置缺口：B7 §七.4「月结成本结转自动化」——月折/底薪/提成等月结成本靠财务手工计提，规则散落、无法随经营调整；设备折旧无台账取数源；已封账期间可被事后改账，账实一致性无强制保障。

## 一、目标与边界

### 1.1 目标

1. **结转规则后台可配、随时调整**：成本类型（设备折旧 / 人工成本）× 取数方式（资产台账直线折旧 / 薪酬底薪合计 / 薪酬已审批提成 / 固定额）组合成规则，可指定全部门店或单一门店，可启停、可切换「封账前自动执行」，不写代码、不重启即可调整（竞品对标：金蝶/用友期末结转模板 + 医美 SaaS 主流的「规则引擎 + 试算后执行」模式）。
2. **设备资产台账作为折旧取数源**：设备入账（原值/残值率/折旧月限/起折月）即按月直线法计提，前后端同公式「月折旧 = 原值 ×（1 − 残值率）÷ 月限」；处置当月起停折。
3. **试算 → 执行 → 重算闭环**：`preview` 仅试算不落账；`run` 幂等落账（重复执行返回 duplicated 不双结）；`recalc` 已结转先冲回再重落，成本镜像三表（fund_entry / outbox_record / cost_allocation）同删同落、门店月报同步补刷。
4. **封账前自动结转 + 封账不可改账**：月结封账（MONTH+门店）同事务内自动执行本店所有「封账自动」规则，自动结转失败则封账整体回滚（不封半账）；封账后该期间资金分录一律拒绝（含经营域补录/重投与财务域重算），重放幂等返回 duplicated，永久不可逆；差错走差异调平 ADJUST 计入当前期间。
5. **只读镜像取数、不跨域直读表**：底薪/提成取薪酬系统只读镜像（B9 已铺），设备折旧取本域台账；结转结果只写成本镜像，绝不动实付渠道。

### 1.2 边界红线

| 红线 | 落实方式 |
|---|---|
| **资金红线**：结转只产生成本镜像，绝不生成实付/收银分录、绝不动渠道账户镜像 | 结转分录固定 `subject=TK-DEPRECIATION/TK-LABOR、direction=OUT、source=SYSTEM、channel=null、ref_type=COST`；outbox 对账台账负额、channel 空；DB 实测 18 行结转分录全部 SYSTEM/channel 空，无 CASH/微信/支付宝实付分录，渠道账户镜像零变动 |

| 写接口四件套 | 入参校验（calcMode 非法 400 中文枚举提示、FIXED 必须单店且 fixedAmount>0 400 中文、pending month 必填缺省 400）；幂等键 `CARRY:{ruleId}:{yyyy-MM}:{storeCode}` + bizRef `{ruleId}:{yyyy-MM}:{storeCode}`；全审计（规则/资产/结转/封账 FIN_SETTLE/CLOSE、封账自动 AUTO_ON_CLOSE）；中文错误 |

| 权限 | 查看 `finance:view`；规则/资产/结转执行 `finance:cost:edit`；发起封账 `finance:settlement:edit`；封账记录查看 `finance:settlement:view` |
| 数据域 | 门店角色只能看/结本店；全部门店规则（store_code 空）仅集团角色可维护；FIXED 固定额强制单一门店 |

| 演示播种不碰生产库 | CostCarryDataInitializer / CommissionDataInitializer 均以 spring.datasource.url contains("meiyun_seed") 门控，prod 库零演示数据 |

## 五、问题与教训

### 5.1 缺陷：carry/run 500 两根因（首发即拦截）

1. **outbox txn_no 列宽不足**：结转 bizRef 为复合格式 `{ruleId}:{yyyy-MM}:{storeCode}`（种子规则 26 位、自建规则最长约 40 位），超出 outbox_record.txn_no 原 VARCHAR(24)，JPA save 触发 value too long，整笔结转事务回滚。修复：V8 Flyway 扩到 VARCHAR(64)（与 idem_key 同宽，纯 ALTER 可重入）+ OutboxRecord 实体 @Column(length=64)。
2. **演示播种器无门控污染 prod**：CostCarryDataInitializer/CommissionDataInitializer 启动即在 meiyun_core 播 SST 演示规则/资产。修复：两个播种器均加 spring.datasource.url contains("meiyun_seed") 门控，并手工清理 prod 已播数据。

### 5.2 缺陷：recalc 两缺陷（重算不干净）

- **现象**：recalc 后 outbox_record 残留孤儿行（fund_entry 删了 outbox 没删）；revenue_monthly 月报仍显示旧成本数。
- **根因**：初版 recalc 只删 fund_entry/cost_allocation；月报 recompute 未接线、且零额行未清除。
- **修复**：OutboxRepository.deleteSystemCarry 按 `txn_no like 'CCR%:{monthToken}:%'` 同删（三表同删）；recalc 后 Stream.concat 合并「删除涉及门店 + 当月镜像门店」逐店 recomputeRevenueMonthly，purgeZero=true 双零删行。验证：recalc 重落 10 行、月报 6 店补刷恒等、无孤儿/残留。

### 5.3 缺陷：seed 登录 401（脚本容器名精确匹配漏重启）

- **现象**：seed 重置后 SE101 登录 401；staff 43 人 login_name/password_hash 未回填。
- **根因**：setup-seed-db.sh 用 `grep -qx "$SEED_ORG_CONTAINER"` 精确匹配容器名，而 compose 给部分容器加了项目哈希前缀（`c2bf5413b2b6_meiyun-seed-org-service` 等），org-service 未被重启 → RbacDataInitializer（ApplicationRunner）未跑 → 凭证未播种。
- **修复**：org/marketing/finance 三处统一改为后缀匹配 `grep -E '(^|_)meiyun-seed-<service>$'` 解析实际容器名再 restart；重置后手动重启 org-service 验证：staff 43/43/43 凭证齐全，SE101/meiyun123 登录成功。

### 5.4 环境与工具备忘

1. shell 代理（7890）拦截 localhost：curl 必须 `--noproxy '*' -k`，跑脚本前 `export no_proxy='*' NO_PROXY='*'`。
2. seed 栈容器名混杂（customer/txn/finance/gateway/frontend 短名；org/audit/marketing/store 带哈希前缀），任何按名操作容器的脚本都应用后缀匹配。
3. 结转/封账审计与错误消息全中文；金额全程 Long 分，月折旧两级四舍五入（50,000,000→395,833 等），前后端同公式。
4. DevTools MCP 的月网格等 transient 弹层 uid 在快照间易失效，交互类验证优先选稳定元素；月份相关业务行为以 API 层验证为准。
