## §1 范围与目标

把「冷静期判定＋违约金自动计算」从**纯前端估算**（stores/contract.ts `inCoolingPeriod`/`refundEstimate`，后端无强制）收编为**后端唯一强制口径**，并挂接既有退款（RF）/退卡（CC）双执行链：

- 签署合同后冷静期内可无责解约（违约金 0、全额退）；
- 冷静期后解约按合同 `penalty_rate` 基点自动计违约金，从应退额扣留；
- 全链复用既有审批中心（ApprovalTodo）、三段级联资金拆分、outbox 资金分录与幂等体系，零新审批模块、零新权限码、网关零改。

**不做**（列 §7 移交）：合同多订单累计核销服务化、解约后卡资产核销联动、refundTerms 富文本渲染、电子签署。

## §3 D1-D8 定案（按推荐授权直拍）

- **D1 挂接形态**：RF/CC 双链挂 `contractNo`（一单对一合同，合同为判定依据）。`CreateRefundCmd`/`CreateCardCancelCmd` 尾部增 `contractNo` 可空——**空＝旧链全兼容零行为变化**。
- **D2 冷静期窗口**：默认 **7 天**（contract.cooling_days 逐单可覆写；B85 实体默认 7＋前端表单默认 7＋B85 §1.2「通行 7 天」三源一致）。判定＝`effectiveAt.plusDays(coolingDays).isAfter(OffsetDateTime.now())`（秒级，期内含边界）。仅「生效中」合同可挂退款/退卡（草稿/已履行/已终止 400 中文）。
- **D3 违约金口径**：期内 `penaltyAmt=0`（无责全额退）；期后 `penaltyAmt=Math.round(基数×penaltyRate/10000.0)`（分，HALF_UP）。**违约金语义＝从应退额扣留（非额外收费）**。RF 基数=paidAmt（须≤合同 totalAmount）；CC 基数=balance（卡内余额）。与前端 refundEstimate 口径逐字对齐，后端为唯一事实源。
- **D4 RF 链执行**：createRefund 合同四重校验（存在/生效中/客户 customer 匹配/paidAmt≤totalAmount）→自动判定→**实退 refundAmt=paidAmt−penaltyAmt 后端算**（contractNo 非空时手传 refundAmt≠计算值→400「合同退款金额由后端按冷静期/违约金自动计算」）→`tierFor(实退)` 定级→审批/三段拆分/outbox 全复用零改→TxnRefund 增 `contract_no`/`penalty_amt`/`contract_snapshot` 三列（ddl-auto 零迁移）→`emitRefundConfirmed` 增 **RF-PENALTY/IN 违约金收入分录**（penaltyAmt>0 时一条；RF-DEPOSIT/IN 既有分录不动，两笔合计=预收总冲回，账平）。
- **D5 CC 链执行**：createCardCancel 同款判定（基数=balance）→`fee=penaltyAmt`（期内 0/期后 balance×rate/10000）→feeRate=rate/10000（4 位 HALF_UP）→feeManualOverride=false→**medical 禁忌免收优先于合同违约金**（medical=true→fee=0，人道优先）→Java `rateOk` 增第四通道 `|| contractNo 非空`→**chk_tk_fee_override 库内 DDL 放宽双库**：`DROP CONSTRAINT`＋`ADD CHECK (is_medical_contraindication OR fee_manual_override OR (fee=(balance/10)) OR contract_no IS NOT NULL)`→chk_tk_balance 恒等式天然满足零改→`emitCardCancelConfirmed` 三条分录零改（fee 段即违约金收入，fee=0 跳过分支天然适配期内）。
- **D6 快照与审计**：`contract_snapshot` TEXT 落 RF/CC 双表（JSON：contractNo/title/effectiveAt/coolingDays/penaltyRate/inCooling/基数/penaltyAmt/judgedAt）——判定时点快照，合同后续变更不溯既往；audit CREATE payload 带快照关键字段；详情端点返回快照供前端展示。
- **D7 防重号治理**：ContractService.nextNo AtomicLong 内存自增→**库内 maxSeqOfDay**（ContractRepository `@Query` LIKE 前缀取 MAX，仿 `refundRepo::maxSeqOfDay`/`cancelRepo::maxSeqOfDay` 先例）＋contract_no PK 唯一约束兜底（撞号 DataIntegrityViolation→409 中文「合同号冲突，请重试」）。
- **D8 权限与兼容**：零新权限码（复用 refund:create／cardCancel:create 既有）；网关零改；前端适配层 contractNo/penaltyAmt/contractSnapshot 可空（旧单回落展示「—」）。

## §6 风险与对策

| 风险 | 对策 |
|------|------|
| 期界秒级口径（前端 ms vs 后端 OffsetDateTime） | 后端 `plusDays().isAfter(now)` 唯一权威；前端仅展示预估，金额以后端回包为准（D3/D8） |
| 合同金额与多订单拆分精度 | v1 paidAmt 声明制＋≤totalAmount 上限；累计核销服务化列 §7 |
| chk 放宽影响旧链 | 新 chk 为原三通道**并集**加豁免，旧链（contract_no NULL）约束不变；回归实证 fee=balance/10 落库（§5-6） |
| nextNo 改库内查询并发撞号 | PK 唯一约束兜底＋DataIntegrityViolation→409 重试提示（D7） |
| RF 侧 refundAmt 改后端算的兼容性 | contractNo 空走旧逻辑（手传 refundAmt 直用），零行为变化（D1/D4） |
| 赠金/卡本金拆分与违约金 | 拆分基数＝扣减后 refundAmt，赠金段无资金分录现状不动；违约金独立 RF-PENALTY 分录（D4） |
