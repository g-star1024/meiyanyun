## 二、后端实现要点（txn-service，端口 8083/18083）

### 2.1 数据模型（db/schema_m4_core.sql，双库 meiyun_core + meiyun_seed 均已应用）

- `writeoff_record`：核销记录表，核销单号 `WO` 前缀（当日最大序号 +1，禁 AtomicLong）。
- `txn_refund`：退款单表，退款单号 `RF` 前缀，状态机 PENDING_REVIEW → PENDING_FINANCE → REFUNDED / REJECTED。
- `txn_card_cancel`：退卡单表，退卡单号 `CC` 前缀，同审批状态机。
- `approval_todo`：**统一审批待办表**，审批单号 `AP` 前缀；字段含 status（PENDING/APPROVED/REJECTED）、stage（REVIEW/FINANCE）、assignee、co_signers（加签人，去重）、history（jsonb：SUBMIT/TRANSFER/ADD_SIGN/APPROVE/REJECT 动作链）。
- `txn_order` 补充：`status` CHECK 约束增加「已核销」枚举；新增 `writeoff_at` 列（整单核销时刻）。

### 2.2 审批状态机

- **L1**（退款金额 < 500,000 分，即 < ¥5,000 档内由前端阈值 ¥1,000 切分）→ 直达 `FINANCE` 阶段；
- **L2 / L3**（≥ ¥5,000 / ≥ ¥20,000）→ 先进 `REVIEW` 阶段复核，复核通过转 `FINANCE`；
- 四个审批动作：`approve`（通过）/ `reject`（驳回）/ `transfer`（转交，assignee 变更留痕）/ `addSigner`（加签，co_signers 去重追加）；
- 业务单联动：审批终审通过 → 退款单 REFUNDED / 退卡单进入资金环节；驳回 → REJECTED。

### 2.3 写链路四件套（铁律：校验 → 幂等 → 审计 → 中文错误）

- 参数校验 400、幂等冲突 409（重复核销/重复退款）、无权限 403，错误文案全中文、零技术码外露；
- 全部写动作落 `audit_log`（audit-service），payload 为合法 jsonb，记录操作人/门店/单号/金额/审批动作全字段；
- audit_log 哈希链（prev_hash/cur_hash）完整，无断链。

### 2.4 本会话修复的缺口：writeoff_at 恒 NULL

- **发现**：DoD-5 SQL 对账时发现 4 张已核销订单 `writeoff_at` 列恒为 NULL；grep 源码确认 `TxnOrder` 实体**根本未映射该列**（非仅漏 set，是字段缺失）。
- **修复**：
  1. `TxnOrder.java` 增加 `@Column(name="writeoff_at") private OffsetDateTime writeoffAt;`
  2. `M4FlowController.orderWriteoff` 核销回写处补 `o.setWriteoffAt(w.getCreatedAt() != null ? w.getCreatedAt() : OffsetDateTime.now());`（首次仅用 `w.getCreatedAt()` 复验仍为 NULL——回写时刻该值可能未填，加 now() 兜底后生效）
  3. `schema_m4_core.sql` 末尾追加幂等回填 UPDATE：以 `writeoff_record.created_at` 补齐存量已核销订单，重复执行不覆盖已填值；双库应用。
- **复验**：新核销单 WO20260902-000004 的 writeoff_at 正确写入；终态 4 单已核销全有值，其余 608 单非核销全 NULL。
