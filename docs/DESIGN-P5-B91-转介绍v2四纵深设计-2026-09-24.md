## 2. 定案（D1-D10）

### D1 自动发放＝deal() 钩子自动登记 PENDING，人审发放兜底
deal() 成交钩子内按配置自动登记奖励，初始状态 **PENDING**，复用 v1 `grantReward/rejectReward`（referral:approve）人工确认流。资金链路保留人审兜底；「自动」指自动登记进入发放流，非免审直发。deal() 状态机 VISITED→DEAL 一次性 + idem_key 唯一约束，重放天然幂等。

### D2 阶梯奖励触发语义
deal() 时统计 referrer **全局累计 DEAL 单数 total（含当前单，不过滤活动）**，命中 `ladders.threshold == total` 的阶梯项各登记一条。梯子配置为 GLOBAL 单行（非活动维度），统计口径即全局。仅 deal() 一个触发点（CONFIRMED/VISITED 场景留 v1 手动登记）。

### D3 二级返佣做（levels 已建模）
- level 1：当前单 referrer，amountCents = round(dealAmountCents × rate)。
- level 2：追溯上线＝`refereeCustomerId = 当前单 referrerId 且 status ∈ (PENDING/CONFIRMED/VISITED/DEAL)` 的最新一条 referral 之 referrerCustomerId；存在且 ≠ 当前 referrer 则按同式发放。
- rate ≤ 0 或计算金额 ≤ 0 跳过登记。

### D4 词表映射（service 层，前端词表→后端 chk 词表）
| 来源 | 前端词表 | 后端 rewardType | 金额口径 |
|---|---|---|---|
| 阶梯 | CASH | **GRANT**（固定额赠送） | 元 ×100 → amountCents |
| 阶梯 | POINTS | POINT | amount 直落 points（积分非元，不 ×100） |
| 阶梯 | COUPON | COUPON | 元 ×100 → amountCents |
| 层级 | —（rate） | **COMMISSION**（按比例返佣） | round(dealAmountCents × rate) |

### D5 idemKey 扩展（v1 基底 + 来源段，≤80）
v1 手动登记格式不变：`{referralId}:{triggerEvent}:{rewardType}`。
自动发放加来源段避免同 key 冲突（侦察发现：阶梯 CASH→GRANT 与层级→COMMISSION 若不区分会同 `{id}:DEAL:{type}` 撞唯一约束）：
- 阶梯：`{referralId}:DEAL:{mappedType}:T{threshold}`
- 层级：`{referralId}:DEAL:COMMISSION:L{level}`

最长约 `RF20260924-000001:DEAL:COMMISSION:LADDER123` ≈ 40 字符 < 80 ✓。登记走 v1 同款「findFirstByIdemKey 预查 + DataIntegrityViolationException 兜底重查返回既有」。

### D6 V50 迁移：referral_reward 加受益人列（仅一列，无新表）
二级返佣受益人 ≠ 当前单 referrer，实体无受益人字段 →
`ALTER TABLE referral_reward ADD COLUMN beneficiary_customer_id VARCHAR(24)`（NULL=所属单推荐人；L2 填上线客户号）＋ COMMENT。不加索引（无独立查询场景，列表富化走 referral 关联）。活动 CRUD 复用 V47 表，零 DDL。

### D7 campaign_id 建单校验
create()：campaignId 非空时校验活动存在且 status=ONGOING，否则 422「活动不存在或未在进行中」；空=不挂活动（兼容现状）。referee 归属门店 DataScope 校验保留。

### D8 活动统计列
GET /campaigns 行加 `invited`（campaignId=X 的 referral 数）/ `converted`（其中 status=DEAL 数）。ReferralRepository 加 `countGroupByCampaignId` 一次 group by（防 N+1），空 campaignId 不计入任何活动。前端 refreshCampaigns 接真去恒 0。

### D9 valid_days 建单接线
create()：`body.validDays` 显式传 → 1-365 校验后优先；未传 → 取 GLOBAL config.valid_days；无配置行 → 30 兜底。

### D10 活动 CRUD 三端点 + 前端范围
- `POST /campaigns` 创建：name 必填 ≤64、startAt/endAt 必填且 endAt ≥ startAt、storeCode 可空（空=全部门店）、remark ≤256、status 默认 DRAFT；单号 RC+8位日期-6位当日序号（nextCampaignNo，synchronized 同 RF/RW 范式）。
- `PUT /campaigns/{id}` 编辑：name/dates/storeCode/remark；ENDED 冻结 409。
- `PUT /campaigns/{id}/status` 状态流转：仅正向 DRAFT→ONGOING→ENDED（body.status 目标态校验，跳态/回退 409）。
- 权限 referralCampaign:edit；审计 `REFERRAL_CAMPAIGN` / CREATE / UPDATE / STATUS；DataScope：storeCode 非空须本店可写（canReadOwned 同口径），空=连锁行按既有列表可见性口径。
- 前端：M5ReferralView 页内新增「邀请活动」区块 + 新建/编辑弹层（无新路由新页面）；关系链列表头加「新建绑定」入口（推荐人/被推荐人走 /customer/search，所属活动下拉=ONGOING 活动可空）。

## 5. 自动发放链路（deal 钩子伪代码）

```
deal(id, body):
  r = getOwned(id); requireStatus(r, VISITED)
  r.status=DEAL; r.dealAt=now; r.dealAmountCents=amt; save(r)
  cfg = campaignConfigRepo.findById('GLOBAL').orElse(null)
  if cfg != null:
    ladders = parse(cfg.ladders); levels = parse(cfg.levels)
    total = referralRepo.countByReferrerCustomerIdAndStatus(referrerId, 'DEAL')  // 含当前单
    for l in ladders where l.threshold == total:
      type = mapType(l.type)            // D4
      idem = "{r.id}:DEAL:{type}:T{l.threshold}"
      register(type, DEAL, amount=l.type=='POINTS' ? null : round(l.amount*100),
               points=l.type=='POINTS' ? long(l.amount) : null,
               beneficiary=null, remark=l.desc, idem)
    for lv in levels where lv.rate > 0:
      cents = round(amt * lv.rate); if cents <= 0: continue
      if lv.level == 1: beneficiary = null                          // 所属单 referrer
      else: up = uplineOf(referrerId); if up == null: continue; beneficiary = up
      idem = "{r.id}:DEAL:COMMISSION:L{lv.level}"
      register(COMMISSION, DEAL, cents, null, beneficiary, lv.desc, idem)
  audit DEAL（既有）
```

- `register()` 与 v1 createReward 同校验同幂等（预查 + 唯一约束兜底），状态 PENDING（D1）。
- `uplineOf()`：refereeCustomerId=referrerId 且 status ∈ ACTIVE_STATUSES 的最新一条（createdAt desc）之 referrerCustomerId。
- Repository 新增：`countByReferrerCustomerIdAndStatus`、`findFirstByRefereeCustomerIdAndStatusInOrderByCreatedAtDesc`、`countGroupByCampaignId`。
- deal() 单事务同步执行，奖励条数 ≤ 命中阶梯数+2，性能无虞；单条失败整体回滚（成交与奖励登记同原子，避免半态）。

## 9. 风险与边界

- **POINT/COUPON 出账范围外**：自动登记 POINT/COUPON 奖励 grant 后仅落 referral_reward 记录（v1 手动登记同口径）；积分入账/券发放联动留后续批次（04 另行登记）。
- **种子活动统计口径**：存量 referral 单多未挂 campaign_id，RC-SEED-001 接真后 invited/converted 显示 0 属正确口径（非 bug）。
- **阶梯门槛跳跃**：total 不会跳变（一单 +1），但「补登历史成交」场景下 threshold < total 的阶梯不追溯（仅 == 命中，口径写死防滥发）。
- **层级成环**：referee 唯一活跃绑定索引（uk_referral_referee_active）保证上线链不成环；uplineOf 取最新一条即直接上线。
- **金额四舍五入**：round(dealAmountCents × rate) 到分，单边无累计误差诉求。
- OCR 门禁：火山额度 09-25 重置，如遇 429 按铁律 12A 注明跳过。
