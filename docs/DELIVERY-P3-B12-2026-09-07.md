- 批次：P3-B12（P3 运营配置四域之「域一」）
- 日期：2026-09-07
- 上批：P3-B11（月结成本结转自动化，已交付）
- 本批性质：功能开发（txn-service 渠道配置域 + finance-service 账单勾兑域 + 前端两个页面域）+ 真实双栈部署验证 + 配置闭环 / CSV 导入 / 勾兑全链路 E2E
- 前置缺口：B7 §七.1「非现金渠道账实接入」——微信/支付宝/银行转账等非现金收款，系统收银落账（fund_entry）与渠道实际结算单各记各的，全靠人工月底对一遍，漏单（客户已付、渠道少结）、多单（渠道有、系统无）、手续费差异无系统化排查手段；渠道对接参数（商户号/密钥/费率）也无后台配置入口。

## 一、目标与边界

### 1.1 目标

1. **渠道对接参数「在支付方式里配置」**（落实用户原话）：`/admin/mp-settings` 支付方式配置页由 mock store 切换为真实 `GET/POST /api/txn/pay-channels`，在既有微信支付卡片基础上新增支付宝、银行转账两张渠道卡片（样式零改动，复用既有设计令牌）；商户号、AppID/PID、APIv3 密钥、证书序列号、回调地址、费率（%）均可后台可配、随时启停；密钥类字段写后掩码回显、不下发明文。
2. **渠道结算账单接入与账实勾兑**：财务对账页 `/m6-reconcile` 新增「非现金渠道核对（按月）」tab，支持把渠道后台导出的结算单 CSV 整批导入（落 finance 域账单台账），以「门店 + 订单号」为勾兑键，把**系统账**（fund_entry 非现金渠道收银收款分录）与**渠道账单**逐单比对，输出已勾兑 / 漏单（系统有账单无，重点排查）/ 多单·未入账（账单有系统无）/ 金额不符 / 退款·失败行，以及手续费汇总（竞品对标：有赞/微盟的「资金流水对账」与金蝶「银企对账单勾兑」——按订单号自动勾对、差异单列、不自动补账）。
3. **诚实降级、不臆造外部数字**：渠道真实 API 拉单（需商户真实密钥 + 渠道侧授权）属后续迭代；本批在凭据未接入前，账单以「门店财务从渠道后台导出 CSV 再导入」为准，未导入账单的渠道 `billsAvailable=false` 并给中文引导，绝不凭空编造渠道结算数。
4. **只读镜像 + 配置分离**：渠道配置（属交易集成参数）落 txn 域；账单与勾兑（属财务核对）落 finance 域；勾兑只读取系统 fund_entry，不跨域直读 txn 订单表，不回写交易域。

### 1.2 边界红线

| 红线 | 落实方式 |
|---|---|
| **资金红线**：账单只用于勾兑核对，绝不据账单补造任何实付渠道分录（fund_entry） | 账单导入只写 finance 域 `pay_channel_bill` 对账台账；勾兑服务只 `SELECT` 系统 fund_entry 做比对、产出差异清单，全链路无任何 fund_entry/outbox/账户镜像写动作；页面常驻红线文案「账单只用于勾兑核对，不会据账单补造任何实付渠道分录」；DB 实测导入前后 fund_entry 零新增 |
| **诚实降级**：不臆造渠道结算数据 | 未导入账单的渠道 `billsAvailable=false`，勾兑卡显示「暂无 xx 账单，未做账实结论」+ 中文导入引导；prod 无种子账单时三渠道全部降级，系统侧仍真实展示当月 fund_entry 收款与漏单 |
| **密钥不明文下发** | api_v3_key 等密钥类字段保存后回显掩码（`****`），列表/详情接口不返回明文；前端编辑时空密钥框表示「不修改」，不会用掩码覆盖原值 |
| 写接口四件套 | 入参校验（渠道枚举非法 400 中文、CSV 8 列/表头识别/金额非负/结算批次必填逐行中文报错定位到物理行号）；幂等键 `import_batch`（相同批次整批跳过返回既有行数）+ UNIQUE(渠道,订单号,结算批次) 兜底；全审计（配置 upsert/toggle、账单导入均落中文审计）；中文错误 |
| 禁直读别域表 | finance 勾兑不直读 txn 订单/支付表，系统侧只取本域 fund_entry（与 FinanceEventPublisher 的 ORDER_PAID 落账口径逐字对齐）；渠道配置经 txn 域自有接口读写 |
| 权限 | 渠道配置查询 `integration:view`（与「小程序/支付集成设置」菜单一致）；渠道配置新增/更新/启停 `finance:channel:edit`；账单/勾兑查看 `finance:view`；账单导入 `finance:reconcile:edit`。均经自定义 `@RequirePerm` 注解 + 网关鉴权落地 |
| 金额 / 费率 | 金额全程 Long「分」；费率万分位整数（0.6% → 60），前端回填百分数 `feeRate/100`、保存 `Math.round(percent*100)`；业务表 JPA ddl-auto，种子不进 Flyway（setup-seed-db.sh 同步 DDL + TRUNCATE） |
| 演示播种不碰生产库 | PayChannelDataInitializer 以 spring.datasource.url contains("meiyun_seed") 门控；prod 库 pay_channel_config / pay_channel_bill 均 0 行 |

## 五、问题与教训

### 5.1 缺陷：导入账单 createdAt 不落 / 批量 merge 异常（首发即拦截）

- **根因**：PayChannelBill 的 billId 为提前 set 的分配式 @Id，JPA `saveAll` 对已带 ID 的实体走 **merge** 而非 persist；`@PrePersist` 在 merge 路径上不可靠，created_at 不落。
- **修复**：服务层导入循环内显式 `b.setCreatedAt(now)`，不依赖生命周期回调。

### 5.2 缺陷：多行 CSV 导入每批只落最后一行（merge 互覆丢行）

- **现象**：导入含 N 行的 CSV，DB 只落 1 行（最后一行）。
- **根因**：billId 序号在循环内**逐行**调 `maxSeqOfDay("PCB"+当天+"-%")` 生成；但同一事务内尚未 flush 的行对该查询不可见 → 每行都查到同一最大序号 → 同批 billId 全相同 → merge 按同主键互相覆盖，只剩最后一行。
- **修复**：序号在循环**外**取一次 `long billSeq = repo.maxSeqOfDay(...)`，循环内 `setBillId("PCB"+prefix+"-"+%06d(++billSeq))` 内存递增；批次号 nextBatchNo 同理循环外生成。验证：wxpay 7 行 / alipay 2 行全部落库、billId 连续不重复。

### 5.3 缺陷：费率框显示 float 尾巴（0.6000000238418579）

- **排查链**：源码修复在 → dist bundle 含 `Math.round(feeRate/100*100)/100` → 容器内 bundle 含修复 → curl API 返回 feeRate 为**干净万分位整数 60/55/10**（尾巴不在后端数据）。
- **根因 / 定论**：后端费率本就是干净整数；初版前端直接 `feeRate/100` 回填产生二进制浮点尾巴，已改 `Math.round((feeRate/100)*100)/100`。修复后 `evaluate_script` 读真实 `input.value` = `"0.6"/"0.55"/"0.1"` 干净。
- **工具教训**：navigate(ignoreCache) 后 `take_snapshot` 的 a11y 树可能保留**导航前的陈旧控件值**（快照里的尾巴即此假象，非真实 DOM）；判定真实输入框值必须用 `evaluate_script` 读 `element.value`，不能只信快照文本。

### 5.4 环境与工具备忘

1. shell 代理拦截 localhost：curl 必须 `--noproxy '*' -k`；**直连 seed 网关 18443 返回空响应**，应走前端 nginx 端口（seed 18080 / prod 8080）。
2. 登录响应为**扁平结构** `{token, staffId, staffName, roles, ...}`，token 在顶层，脚本取 `json['token']` 而非 `data.token`。
3. prod 关闭演示快捷登录，须工号/密码表单；seed 快捷登录可用。
4. 前端 `npm run build` = `vue-tsc --noEmit && vite build`，exit 0 即类型检查 + 构建双通过；本批产物 `index-DyyaBGEE.js`。
5. 权限经自定义 `@RequirePerm("权限码")` 注解 + 网关鉴权落地（非 javax @PreAuthorize）；渠道配置查询 integration:view、写 finance:channel:edit，账单查看 finance:view、导入 finance:reconcile:edit。
6. 审计、错误、引导文案全中文；金额 Long 分、费率万分位整数，前后端同口径。
