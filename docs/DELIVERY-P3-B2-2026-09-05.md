## 一、本批目标与边界

**目标**：B1 接通真实台账后遗留两个读链路缺口——① 订单收款渠道已落 `order_payment.pay_method` 但 txn 投影不带、finance 订单分录 channel 硬编码 null，资金日报渠道表全落「未标记渠道」；② `GET /api/txn/writeoff` 仅门店域 + 时间倒序，无卡号/客户/日期区间过滤，客户 360 与卡详情无法查划扣历史。本批把渠道数据接进台账与日报，并补齐划扣查询条件。

**边界（红线，与 B1 一致）**：

- 仍**不新增任何资金写动作**（finance 维持纯只读；不触碰 outbox/account_mirror/prepay_pool 空转三表——移交 B3）；
- 不直读别域表：渠道归并在 txn 内部端点完成投影，finance 仅消费 DTO；
- 样式零改动：前端仅补渠道角标/桶位命名/划扣小节接线；
- UI 模型 ≠ 后端能力处**诚实降级**：历史无 `order_payment` 流水的订单渠道列显「—」，不臆造渠道。

**混合支付口径（用户拍板，DESIGN §4.1 方案 a）**：一笔订单多笔支付（如微信+现金）时，取**该单入账额（postedAmount）最大一笔**的 payMethod 为主渠道，distinct 渠道数 > 1 置 `mixed=true`；渠道桶按主渠道码归并（保证 Σ桶 = 收银实收，不重不漏），桶内出现混合单则桶名展示「混合（主：xx）」；台账渠道列追加「（混合）」角标，摘要 memo 追加「（混合支付）」。

## 五、本批明确不做（移交后续批次）

1. **资金写动作仍为零**：outbox_record / account_mirror / prepay_pool 三表仍无运行时写入方；退款终审不触发 finance 落账/卡状态回写——**B3 合规写**（fund_entry + Flyway 系统表 + 内部写端点 + 本地 outbox 定时重试 + finance 幂等 + ledger-diff 双跑校对）。

3. **成本库存域**：耗材三表/双签动账/cost_allocation 空白；划扣自动扣 BOM 耗材延后；FinBudget/FinInvoice/FinSettings 三页随 B5 进当期——**B5**（用户已拍板三页进当期）。
4. **对账结算加固**：三方对账、settlement 封账、设置页 sys_* 系统表、网关 `/internal/**` 网络隔离（本批内部端点仍仅应用层 X-Internal-Token 拦截）、提成按双签 COMMISSION 工单驱动——**B6**。
