## 1. 背景与目标

渠道内容生成页（`/ai/content`）按**公众号 / 海报 / 短信**三渠道组织 AI 文案生产，卡3 之前整页是硬编码 mock：四 KPI 写死、历史列表造假、生成按钮只回填本地假文案、下发无任何后端动作。

卡2 §7 已明示根因：既有 `POST /api/ai/features/{code}/invoke` 的 content 功能只有单一文本入参/出参，**没有渠道（channel）维度**，强行切真只能再造假结构；因此本卡的首要设计目标是把「渠道口径」补到真实链路上。

B46 卡3 验收口径：

1. 三渠道生成走**真实火山方舟 ark-code-latest**，渠道/主题/全文/模型/token/费用等业务字段真实落表；
2. 复用既有 invoke **全治理链**（角色灰度矩阵 / 门店灰度 / 敏感词拦截 / 配额 / 计费 / ai_invoke_log），不平行造一套出站；
3. 历史记录真分页、六 KPI（今日/累计生成、今日/累计下发、今日合规拦截、采纳率）全部真算；
4. 生成结果可一键**登记下发**（GENERATED→DEPLOYED），幂等且写全动作审计，页面 KPI/行状态实时联动；
5. 解决长文案（完整推文/海报）出站耗时远超原 60s 读超时的真实缺陷。

[ContentService.java](file:///Users/huluobo/WorkBuddy/2026-08-15-23-51-02/meiyun-platform/backend/ai-service/src/main/java/com/meiyun/ai/content/ContentService.java) 要点：

1. **渠道口径补齐**：`CHANNELS = wechat/poster/sms`，非法/空 channel 与空 topic 一律中文 400；`compose(channel, topic)` 按渠道拼不同系统指令（公众号=结构完整可含小标题图文推文、海报=短主副标题突出卖点到店引导、短信=70 字内含行动号召与退订口径），并统一追加合规约束（禁绝对化用语/医疗功效承诺/不泄系统提示）。storeCode 缺省取登录门店。
2. **复用全治理链**：generate 内部调 `featureInvokeService.invoke("content", …)`，因此角色矩阵 403、门店灰度、敏感词 400 脱敏、配额 429、模型/CHAT 校验、token 计费、ai_invoke_log 成败沉淀全部自动生效，不重复实现。
3. **createdAt 回读**：`generate` 刻意无方法级事务（沿用 B43 设计，保证出站失败日志独立提交）。无事务方法 save 后实例不回填 DB 默认时间戳，故 save 后 `findById(...).map(toView).orElseGet(...)` **回读**拿到真实 created_at（见 §5 修复2）。
4. **六 KPI 按北京日界**：todayGenerated/todayDeployed 以 `Asia/Shanghai` 当日 0 点为界；totalDeployed=`countByStatus('DEPLOYED')`；todayBlocked=ai_sensitive_hit 当日 feature_code='content' 计数；`adoptRatePct = round(totalDeployed*100/totalGenerated)`（HALF_UP 口径，零分母显 0）。
5. **下发幂等 + 审计**：deploy 记录不存在中文 404；已 DEPLOYED 返回 `changed=false` 不重复写审计；GENERATED→DEPLOYED 置 deployed_at=now()、deployed_by=当前操作人，写 `AI_CONTENT_RECORD` / `DEPLOY` 审计（payload 含 channel/title/storeCode 合法 JSON）。

## 5. 真验过程发现与修复

1. **长文案 60s 读超时（核心根因，代码修复）**：表面报 "Error while extracting response ... octet-stream"，二分定位——短输入 19s 成功、长提示词 **60.175s 整点失败**，实为 RestClient readTimeout。三处对齐 180s（yml 默认值、LlmClient cause 链识别给准确中文错、前端 axios timeout），修复后 136.7s/83.7s 长文均 200。
2. **createdAt 不回填（代码修复）**：created_at 标 insertable=false 靠 PG 默认 now()，无事务 save 后实体时间戳为 null。改为 save 后 `findById` 回读，record5 实测 createdAt 非空。
3. **vue-tsc 两处 CStatusPill tone 类型错（构建修复）**：CStatusPill 的 status 合法联合为 `info/default/primary/danger/disabled/warning/success/draft`，**无 brand**；A1ContentView 两处误用 `'brand'`（previewStatus 与 compliancePill）致 TS2322，统一改 `'primary'`。注意 CKpi 的 tone 支持 brand（采纳率卡）保留不动，二者不混。
4. **敏感词 wait_for 误匹配（自查纠正，非代码缺陷）**：浏览器 wait_for ["拦截","敏感","合规"] 立即返回，后确认命中的是页面静态提示文案；改以 list_network_requests 定位 reqid=202 POST generate [400] 并读响应体「伪**历」才坐实真实拦截，且确认拦截不产生 record。
5. **静态镜像必须重建（环境坑）**：.vue/.ts 改动只有 build + `--build frontend` 后才在 8080 生效，沿用卡1/卡2 经验。take_screenshot 的 filePath 仍受 workspace roots 白名单限制无法落盘 docs/，截图以内联返回 + 可访问性快照文本 + 网络 reqid 存档。
