## 一、目标与边界

### 1.1 目标

1. **完整售卡下单链路**：客户购卡走 txn-service 收银台 `txn_order` 完整下单/收款/对账——下单（biz_kind=CARD_SALE，模板快照冗余落单）→ 分次收款（cash/card/wxpay/alipay）→ 收齐同事务回调 customer 开卡 → 发 CARD_SALE_PAID 资金事件。
2. **开卡实例化 member_card**：收款收齐后 customer 域以售卡单号幂等开卡（MC+yyyyMMdd-6位），实例落 product_code/card_type/expires_at/sale_no/gift_balance 五字段；疗程卡 total_times=remain_times，储值卡 balance=售卡本金。
3. **首笔卡账本流水**：开卡即写 card_ledger 首笔 RECHARGE 正额（biz_ref=售卡订单号、operator=system），对账恒等式 Σ ledger.amount = member_card.balance；后续门店充值走 RC 单号、operator=真实登录人。
4. **售卡资金联动**：售卡是预收负债而非即时收入——收齐只发 CARD_SALE_PAID → 单条 **RF-DEPOSIT/IN/CASHIER 预收分录**（不发 RF-REVENUE），finance 侧增预收池 + 商户户镜像；后续疗程/储值核销走现成 emitWriteoffDone 成对结转。
5. **前端 CardCourseView 全链路去 mock**：选客户 → 选在售模板 → 下 card-order → 收银台收款 → 卡列表/余额/次数/有效期 → 卡流水台账，全部接真实 API；页面视觉与交互样式零改动。
6. **双栈真实验证**：seed 栈 API E2E + 数据域全链路核查 + 浏览器真实售卡/充值（E014 超管三笔 + SE001 店长一笔售卡+一笔充值）；prod 栈部署 + 建列 + 网关冒烟（不制造业务残留）。

### 1.2 边界红线（四项范围拍板落实）

| 决策点 | 结论 | 落实方式 |
|---|---|---|
| **链路深度** | **完整售卡下单** | 走 txn_order 完整下单/收款/对账，不做「直发卡」旁路；收款收齐才开卡，部分收款不开卡 |
| **member_card 字段** | **四个全补（+card_type 快照）** | product_code（产品溯源）、expires_at（有效期，validityDays>0 则 now+天数，否则 null 长期有效）、sale_no（售卡单号=orderNo，幂等键）、gift_balance（赠金，本批售卡固定 0，充值赠金留后续）；另加 card_type 快照（CARD/COURSE），避免回查 catalog |
| **开卡首笔流水类型** | **复用 RECHARGE** | 首笔写 RECHARGE 正额（amount=售卡本金、biz_ref/order_no=售卡单号、operator=system），不动 Flyway V5 card_ledger CHECK 约束（change_type IN RECHARGE/CONSUME/REFUND/ADJUST）；开卡 vs 门店充值以 biz_ref 前缀（OD 售卡单 / RC 充值单）与 operator 区分 |
| **前端去 mock 范围** | **CardCourseView 全链路** | 选客户+选在售模板+下 card-order+收款+卡列表+流水台账全接真实 API；样式零改动只换数据源 |
| **价格不信前端** | 后端定价 | createCardOrder 经 StoreCatalogClient.getForSale(productCode, storeCode) 取 store 域在售模板，售价/卡名/次数/有效期**以后端为准**；模板快照冗余落 txn_order，收款开卡只依赖 customer 不回查 store |
| **售卡禁储值余额支付** | 拦截 CARD_SALE+balance | PaymentService 对 biz_kind=CARD_SALE 且 pay_method=balance 直接 400 中文（防卡买卡套现、绕开售卡实付资金闭环） |
| **开卡幂等** | sale_no 反查 | customer 域 findFirstBySaleNo(orderNo) 命中即返回既有卡；收款回调网络重试不重复开卡；资金分录 idemKey=CARD-SALE:订单号 |
| **售卡权限** | 三码 OR（前后端对齐） | card-order 端点与前端门控统一 `{prescription:create, prescription:edit, cashier:create}`——咨询师/医生走 create、店长 STORE_MGR 走 edit（无 create/cashier:create，有 prescription:edit）、前台 FRONT_DESK 走 cashier:create；门店充值门控 customer:card:recharge |
| **金额口径** | bigint 存分 | 后端全程分（long），前端元↔分换算；internal 取价出参 priceFen（分） |
| **内部端点鉴权** | X-Internal-Token | /cards/issue 用 internal:card-write、/internal/catalog 用 internal:catalog-read，仅服务间系统身份（perms=["*"]）放行，普通登录人 403 |

## 五、问题与教训

### 5.1 缺陷：售卡权限前后端不一致——店长必 403（浏览器售卡拦截）

- **现象**：SE001 店长（STORE_MGR）在 /card-course 点售卡，前端按钮可点（canSell 含 prescription:edit），但后端 card-order 仅 @RequirePerm("prescription:create")，店长无此权限 → **403**，售卡单下不成。
- **根因**：前端门控按 permission-matrix §4 角色速查用了三码 OR（咨询师/医生 create、店长 edit、前台 cashier:create），后端端点却只挂了 prescription:create 单码——**前后端权限码口径漂移**。
- **修复**：ConsultPlanController.card-order 改 `@RequirePerm({"prescription:create","prescription:edit","cashier:create"})` 三码 OR（@RequirePerm 数组为 OR 语义，AuthInterceptor 遍历任一 hasPerm 放行），与前端 v-perm/canSell 完全对齐；retail-order 保持 prescription:create 不动。重建部署后 SE001 售卡 OD...0004 + 充值 RC...0003 全成功，403 消除。
- **教训**：**权限码必须前后端同源核对**——前端 v-perm 数组与后端 @RequirePerm 数组逐一比对，且要覆盖「该功能目标角色里最弱势的那个」（店长 STORE_MGR 无 create/cashier:create，只有 prescription:edit）反向用例。权限矩阵改一处，前后端两处必须同步。

### 5.2 口径澄清：售卡是预收负债，不发即时收入

- 售卡收齐的钱是商户对客户的**负债**（客户尚未消费），若收齐即发 RF-REVENUE 会虚增收入。本批收齐只发 CARD_SALE_PAID → 单条 RF-DEPOSIT/IN 预收分录（finance 增预收池 + 商户户镜像）；收入确认延后到疗程/储值实际核销时，走现成 emitWriteoffDone（RF-DEPOSIT/OUT + RF-REVENUE/IN 成对结转）。
- 配套禁储值余额购卡（CARD_SALE+balance 400）：防「卡买卡」套现、防绕开售卡实付资金闭环。

### 5.3 环境与工具备忘

1. card_ledger 金额列名是 `amount`（配 balance_after），**非 amount_fen**；txn_order 金额列名是 `amount`（无 total_fen/paid_fen，收款累计在 order_payment.paid_after）——psql 报列不存在时先 `\d 表名` 查结构。
2. shell 代理拦截 localhost：curl 须 `--noproxy '*'`，网关 `-sk https://127.0.0.1:18443`。
3. 开卡幂等键是 sale_no=orderNo（findFirstBySaleNo）；资金分录幂等键 idemKey="CARD-SALE:"+orderNo。
4. operator 口径：开卡首笔 system（内部端点），门店充值/收款取 DataScope.currentActor() 真实登录人工号，请求体 operator 不可信。

1. **疗程/储值核销写链路**：疗程次卡扣减、储值余额消费、跨项目核销走 emitWriteoffDone 结转收入——本批只到开卡 + 预收，核销留后续。

3. **卡转赠/过户/退卡/退卡退款**：member_card 状态机里的转赠、退卡、退款流程留后续。
4. **卡销售统计/分成佣金**：售卡报表、咨询师提成挂钩（依赖售卡流水沉淀，本批流水已落库可作数据源）。
