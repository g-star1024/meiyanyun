- 失败时 error_code 存上游消息，截断 512 字符（与列宽一致）。

[V16__ai_invoke_log_error_code_extend.sql](file:///Users/huluobo/WorkBuddy/2026-08-15-23-51-02/meiyun-platform/backend/ai-service/src/main/resources/db/migration/V16__ai_invoke_log_error_code_extend.sql)：DO 块查 information_schema，仅当 `character_maximum_length < 512` 时 `ALTER TABLE ai_invoke_log ALTER COLUMN error_code TYPE VARCHAR(512)`，幂等。实体 [AiInvokeLog.java](file:///Users/huluobo/WorkBuddy/2026-08-15-23-51-02/meiyun-platform/backend/ai-service/src/main/java/com/meiyun/ai/domain/AiInvokeLog.java) 同步 `@Column(length=512)`。

### 3.1 第四缺陷修复：展示映射污染原始枚举（storeScopeText）

真验时发现「门店灰度」下拉在编辑抽屉回显「请选择」。根因：

- `bindRows` computed 在 `...f` 展开后，又用同名展示字段 `storeScope: f.storeScope==='SPECIFIED' ? '指定门店：…' : '全部门店'` **覆盖了原始枚举值**；
- CTable 的 `#col-ops="{ row }"` 插槽传出的是这张展示行，`openBind(row)` 读到的 storeScope 已是中文串；
- [CSelect.vue](file:///Users/huluobo/WorkBuddy/2026-08-15-23-51-02/meiyun-platform/frontend/src/components/CSelect.vue) 用 `options.find(o => o.value === modelValue)` 严格 `===` 匹配 'ALL'/'SPECIFIED'，中文串匹配失败 → placeholder。

修法：展示字段改名 **storeScopeText**（列 key 与映射同步改名），原始 storeScope 随 `...f` 保留。同类教训：表格展示 computed 不得复用原始字段名做中文覆盖，行对象若会回流到编辑表单，展示与原值必须分字段。
