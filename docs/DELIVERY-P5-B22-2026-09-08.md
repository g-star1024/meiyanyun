## 一、目标与边界

### 1.1 目标

1. **push 写链路四件套收口**（营销唯一真实写接口）：`PushService.send()` 顺序——参数校验（渠道白名单 SMS/WECOM/WECHAT_MP、客户存在、内容非空，Bean Validation 空值 422/业务非法 400 中文）→ 违禁词四类实时校验（医疗承诺/绝对化用语等，命中 400 中文）→ **幂等** dedupKey=SHA-256(customerId|pushType|content) 前 16 位、60 秒窗口 findRecentByDedupKey 命中直接返回原 pushId（不重复落库/不占频控/不重复审计）→ **周频控** DbRateLimiter（key=push:customer:{cid}，7 天窗口，硬上限 weeklyPushLimit 兜底 3，超限 400 中文）→ 落库 → 领域事件 → **全动作审计** audit_log（bizType=PUSH、action=SEND、actor=登录人、payload 含 pushId/pushType/customerId/contentLength/contentPreview 截 50 字）。

## 五、问题与教训

### 5.1 写接口四件套必须在服务层闭环，审计要覆盖「不产生新写」的幂等返回

- push 幂等重放返回同一 pushId 时，**不能**再写审计/再占频控——本批把幂等判断放在频控与审计之前，重放路径直接 return 原记录，实测 audit_log PUSH 仅 1 条、频控不被重放消耗。
- 教训：幂等不是「防重复报错」，而是「重复请求返回相同结果且无副作用」；审计/频控/库存等副作用必须在幂等判定之后。

### 5.2 超管/大区账号的「无门店」不是异常，是写链路必须设计的正常分支

- 超管 E014 store_code 为空，券核销又必须落门店编码。硬编码 SST01 在 prod（ST-XX-000 体系）解析不到名称。正确做法是把「无门店账号」当作一等场景：登录门店 → 远程首家真实门店 → 最终降级，三级兜底且门店名始终随编码解析。
- 教训：**凡是「必须落某主数据编码」的写链路，都要回答「上下文拿不到该编码时怎么办」**；降级编码应是真实存在的记录而非编造值，且远程兜底优先于本地硬编码。

### 5.3 服务间取数走内部端点 + token，不直读别域表

- 营销核销需要门店名，按铁律不 JdbcTemplate 直读 store 库，而是 store-service 暴露 /internal/first（@RequirePerm internal:name-map + X-Internal-Token）。这样门店编码体系（prod ST-XX / seed SST01）的差异由 store 域自己消化，营销域无需感知。

### 5.4 环境/部署备忘

1. **`mvn compile` 不重打 fat jar**：只更新 target/classes；改完代码必须不带 `--skip-build` 跑 deploy（触发 mvn package）或先手动 package，否则 --skip-build 会 cp 旧 jar。本批 marketing 新类首次复验不生效（容器 jar javap 无 resolveFirstStore）即此因，全量重打后指纹变更生效。
2. zsh 下 curl URL 含 `?` 必须整体加引号（否则 no matches found glob 报错）；push quota 端点是**路径变量** `/push/quota/{customerId}` 非 query。
3. 登录 token 在响应**顶层** `token` 字段（253 字符）；E014=蒋IT，SUPER_ADMIN，store_code 为空（走核销兜底分支）。
4. 门店编码两套体系：prod 库 ST-XX-000（ST-SH-001 上海旗舰店）；seed 库 SST01-SST05（SST01 上海徐汇店）。
5. 券扫码码 = coupon_template.coupon_code（NEWBIE88/VIP85/WATER500），coupon_id 是 CPN-SEED-* 主键；折扣券 faceValue=折扣×10（85 折→订单×15% 计 discount）。
6. Bean Validation 空值经 GlobalExceptionHandler 返回 **422**「参数校验未通过：…」；业务错误 400 {error:BUSINESS_ERROR, message:中文}。

5. **短视频/直播写接口**：直播开播/结束、短视频发布为状态/记录展示，挂链成交回写未接真实交易 → Backlog。
6. **Dashboard 导出报告/订阅周报**：营销总览「导出报告」「订阅周报」为按钮占位 → Backlog（订阅可复用通知偏好渠道位）。
7. **老带新（referral）mock**：m5-referral 转介绍页与 m5Core 转介绍渠道为 mock，到期重分配依赖营销渠道 + 定时任务 → Backlog（ROADMAP 已登记「转介绍到期重分配」）。
