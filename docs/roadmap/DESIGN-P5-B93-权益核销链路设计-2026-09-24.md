### 0.3 核销底座范式（两套，读源码核实）

- **CouponWriteoffService**（marketing，M5-12 扫码核销台）：校验链 参数→FORGED（券码不存在）→DUPLICATE（已核销）→EXPIRED（停用/过期/用完）；**异常不抛 400，落流水 status≠OK + reason，返回 ok=false**（saveAbnormal）；WR 单号 noGen.next 数据库 Like 序号；操作人 `DataScope.currentActor()`（请求体 operator 不可信）；门店三级链 currentStore()；全动作审计。
- **WriteoffDeskService**（txn，M2 划扣核销台）：任务生成（签到自动/WALKIN 手工）→双签执行→异常标记/解除；扣次/扣额经 CustomerCardClient 调 customer 权威卡台账（**行锁 + WO 单号幂等 + CONSUME 流水**）；bizType=WDESK JSON payload 审计；非法入参中文 4xx。
- B93 取舍：**核销动作落 customer 域**（权益权威在 member_level/customer，仿卡台账 WO 单号幂等先例）；形态取 CouponWriteoffService「异常落流水 ok=false」＋「状态三态」范式。

## §1 定案 D1-D12（按推荐授权）

- **D1 范围收敛**：仅「次数型免费护理权益」（benefitType=FREE_CARE）结构化落地——定义/钱包实例/核销底座/360 接真四环。折扣类 B62 已闭不动；生日倍率（发分规则）与服务标识类不纳入核销链路（§7 登记）。
- **D2 定义载体**：`member_level` 加列 `free_care_times INT NULL`（ddl-auto 派生零迁移）；NULL 时走 `CustomerService.LEVEL_FREE_CARE` 兜底 Map（普通/银卡/金卡=0、钻石=1、黑卡=2，与现文案对齐）——**与 LEVEL_BENEFITS 等四兜底 Map 同例，不落库回填**。
- **D3 写接口扩展**：`LevelConfigReq` 加 `freeCareTimes`（null=不动本字段；非负整数 0~31，超界中文 400）；`updateLevelConfig` 纳入同态比较与审计 before/after；`MemberLevelDTO`/`LevelCatalogDTO` 双读模型加 `freeCareTimes`（一线开单岗可见等级权益次数口径）。
- **D4 钱包实例（懒发放）**：新表 `member_benefit_wallet`（JPA 派生）：customer_id＋period CHAR(7)（YYYY-MM）＋benefit_type（常量 FREE_CARE）＋level_snap（发放时等级快照）＋total_times/used_times＋@Version 乐观锁；UK(customer_id, period, benefit_type)。**懒发放**：读模型与核销双路径 getOrCreate——当期无钱包且等级次数>0 则建（total_times=等级当期次数）；UK 冲突 catch DataIntegrityViolation 后重读（并发安全）。**快照口径**：月中调级不动当期已建钱包，次期按新等级发放（仿 B62 TxnOrder 等级快照先例）。
- **D5 核销写链路**：新表 `member_benefit_writeoff`：writeoff_no（BW 前缀单号，仿 customer 域卡台账 WO 单号生成先例，卡1 核实复用既有生成器）＋customer_id＋period＋benefit_type＋level_snap＋project_name（手输护理项目名 ≤40 字必填）＋status（OK/NO_WALLET/EXHAUSTED）＋reason＋**client_request_id VARCHAR(64) UK（前端 UUID 幂等键）**＋operator（DataScope.currentActor()）＋store_code/store_name＋created_at。校验链：参数→客户存在且未合并→当期钱包（无=NO_WALLET）→剩余次数（0=EXHAUSTED）→OK（行锁 used_times+1）。**异常落流水 ok=false 不抛 400（仅参数非法中文 400）**，仿 CouponWriteoffService.saveAbnormal。**幂等**：client_request_id UK 命中直接返回既有流水（不重复扣次）。全动作审计 bizType=BENEFIT action=WRITEOFF（payload 含 before/after 剩余次数）。
- **D6 权限点**：新增 `benefit:writeoff`——PermissionMatrix 目录＋角色挂点仿 couponWriteoff:verify 三处（前台/咨询师/店长等一线核销岗）；钱包/流水读模型走 `customer:view`（360 页既有门槛零新增）。
- **D7 读模型**：`GET /customer/{id}/benefits`（customer:view）→ `{ wallets:[{benefitType,period,levelSnap,totalTimes,usedTimes,remaining,monthQuota}], writeoffs:[近 20 条流水倒序] }`；懒发放在此触发（getOrCreate 读路径）。
- **D8 前端 360 接真**：权益卡升级——结构化「免费护理」行（当期剩余 X/Y＋等级月配额）＋「核销」按钮（v-perm benefit:writeoff，无权限隐藏）＋核销弹层（护理项目名输入＋确认，提交中禁双击）＋近 5 条核销记录；文案清单保留在结构化卡下方（展示层与执行层并存）。**不新建 store**：钱包/流水/核销动作挂 api 直调＋视图内 ref（仿 B62 卡2 memberLevel computed 轻量先例）。
- **D9 并发/幂等**：client_request_id UK（重复提交/双击/重放返既有流水）＋钱包行锁扣次＋@Transactional 边界＋前端提交中按钮禁用双保险。
- **D10 门店口径**：核销记录 store_code/store_name 取 DataScope 当前门店，缺省落客户归属门店；DataScope 门店 API 卡1 实现时核实（券核销 currentStore 三级链为 marketing 域实现，customer 域不照搬三级链、取不到即客户归属门店兜底）。
- **D11 勾销口径**：批末 04 L73 **整行勾销**（discount 半项 B62＋benefits 半项 B93 全闭）；02 L16 注记更新；03 四行＋00 顶条＋01 changelog；**纵深批数字不变 ✅118/🔧1/⬜9=128≈92%**（同 B50-B79/B89/B91/B92 先例）。
- **D12 不挂 txn 计价**：免费护理「订单免单抵扣」联动（txn createOrder 计价点/internal 端点）不纳入本批，§7 登记 04 新行预案（后续专项）。

## §3 端点契约（customer-service /api/customer 前缀）
