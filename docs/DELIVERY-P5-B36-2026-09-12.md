## 3. 卡3：StoreNameResolver 远程故障与业务不存在严格分层（`a43d299`）

### 3.1 问题与语义依据

store-service `GET /api/stores/name-map?codes=...` 对未知编码的响应是 **200 + 子集 Map**（`findAllById` 行为，见 StoreController L61-72）：

- 200 响应中**缺码** = 该编码在门店表中真不存在 → 业务校验不通过，应 **400**；
- 连接失败/超时/4xx/5xx = 门店主数据服务故障 → 写链路应 **503** 提示稍后重试，**不得降级成 400** 误导用户「门店不存在」。

旧实现两类都回落到「原样返回编码」，无法区分。

### 3.2 改法（新增严格版，旧方法零破坏保留）

- 新增 `StoreServiceUnavailableException`（marketing 包，携带 cause）。
- `StoreNameResolver` 重构为三方法：
  - `resolveNames(codes)` **宽松版**：catch 故障降级返回空 Map，仅保留给「编码回显」「不可用即放行」的非阻断路径；javadoc 明示空 Map 无法区分故障与全不存在，**写链路禁用**；
  - `resolveNamesRequired(codes)` **严格版**：故障直接抛 `StoreServiceUnavailableException`，200 缺码正常返回由调用方判 400；
  - `fetchNames(codes)` 私有：唯一远程取数出口，空/空白入参不发请求，所有 `Exception`（含 RestTemplate 传输异常与 HTTP 错误状态）统一包装成专用异常。
- `MarketingCfgService.validateFallbackStore`（写链路 /m5-settings 保存）改严格版：捕获专用异常转 **503**「门店主数据服务暂不可用，暂时无法保存营销设置，请稍后重试」；200 缺码仍 **400**「兜底门店不存在：xxx」。

### 3.3 另两个消费方逐个核实后零改动

grep 全量消费方共 3 处，除写校验外：

- `CouponWriteoffService.resolveStoreName`（L180）：核销详情**券名/门店名回显**，故障时回退显示编码是合理降级，保留宽松版；
- `MarketingAssetService.validateStoreCodes`（L245）：代码注释明示「门店服务不可用降级放行」——资产创建属高频运营动作，主数据短暂故障不应阻断，保留宽松版；
- 同文件 `resolveFirstStore`（L216）：三级兜底末环，全落空本已有 503，不在本卡范围。

## 4. 卡4：txn-service 测试基建从零建立 + grant 支付护栏 7 例（`c0d3583`）

- txn-service 此前**无 src/test 目录、pom 无 starter-test**（全服务历史欠账）。pom 补测试依赖，新建该服务首个测试类 `PaymentServiceTest`（JUnit5 + Mockito 纯单测，无 Spring 上下文）。
- 七例全部围绕 B35 grant 支付的资金安全口径：
  1. 散客订单（customerId 为空）grant → 400「散客订单…」，不触达营销域、不落库；
  2. 同一订单第二笔 grant（历史已有 grant 流水）→ 409；
  3. 售卡单（CARD_SALE）grant → 400「不能使用营销赠金」（断言售卡禁令先于流水查询生效）；
  4. 成功路径：断言 `deduct → order_payment 落库 → 订单置已收款` 的 **InOrder 顺序**（远程扣账必须先于本地记账，防「记账了但没扣钱」），并校验 deduct 入参与 FUND_ENTRY 事件发出；
  5. 营销域 422（赠金不足）透传：订单仍「待收款」、无支付落库、无审计/事件；
  6. 营销域 502（营销域不可用）透传：同上不记账（「未扣款未记账」口径）；
  7. grant+现金混合支付的**现金尾款**：历史已有 grant 流水时不再调营销域、正常走现金完成订单。
- 过程踩坑（已修复）：Mockito 严格模式下例 3 报 UnnecessaryStubbing——售卡单在禁令处即被拒、走不到流水查询，故把测试桩拆为 `stubOrder(o)`（仅 findById）与 `stubOrderWithPayments(o, history)`，售卡用例只打前者。
- **余留（已登记 Backlog）**：M4FlowController grant-balance 端点的「降级 available:false」分支与 MarketingGrantClient HTTP 层尚无服务内单测（curl 轨已实证），随后续控制器层测试批补。
