### 2.4 卡4：治疗执行（txn-service）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/api/txn/consult-plan/{planId}/treat-start` | `consult:review` + `emr:edit` | PAID→TREATING；术前四项必须全部 true，记录房间/备注/开始时间 |
| POST | `/api/txn/consult-plan/{planId}/treat-done` | `consult:review` + `emr:edit` | TREATING→DONE；treatmentNote 必填，落库医嘱/处方，生成 treatEmrId 病历号 |

请求体契约：

```json
// treat-start（扁平，四项缺一不可）
{
  "operator": "SE003",
  "consentChecked": true,
  "contraChecked": true,
  "drugChecked": true,
  "siteChecked": true,
  "room": "R1",
  "note": ""
}
// treat-done
{
  "operator": "SE003",
  "treatmentNote": "治疗过程记录（必填）",
  "prescription": "术后医嘱/注意事项"
}
```

`ConsultPlan` 实体新增字段（JPA ddl-auto:update 自动建列）：

| 列 | 含义 |
|---|---|
| `pre_op_checklist` (TEXT) | 术前四项核对结果 JSON（consent/contra/drug/site + room + note） |
| `treating_at` | 治疗开始时间（PAID→TREATING） |
| `treated_at` | 治疗完成时间（TREATING→DONE） |
| `treat_note` (TEXT) | 治疗过程/操作记录，完成时必填 |
| `treat_prescription` (TEXT) | 术后医嘱 |
| `treat_emr_id` (32) | 治疗记录病历号，完成时生成归档 |

非法状态跃迁（如未支付直接 treat-start）返回 BUSINESS_ERROR 中文错误；PlanView 同步暴露新字段供前端渲染治疗队列。

## 五、seed 栈回归（18080 / 18443 / `meiyun_seed`）

### 5.1 端到端造数真验（非零计数，证明真实联动）

卡5 不是只验证「零值不报错」，而是在 seed 库通过真实 API 造了一条完整业务链后核对计数增长：

1. 建方案单 CP20260909-000005（PENDING）→ start → ACTIVE。
2. submit 首次被拒：`BUSINESS_ERROR 客户未完成《知情同意书》手写电子签名`；补 `consentSignatureDataUrl`（data:image/png;base64）+ consentCustomer/consentConsultant=true 后 → PENDING_REVIEW。
3. approve → APPROVED；sign-emr 自动开单 OD20260909-000003（待收款）。
