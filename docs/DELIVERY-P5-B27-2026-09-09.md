## 2. 后端设计（全部落 txn-service，免改网关）

### 2.1 新表 3 张（JPA ddl-auto=update 自动建，不写 Flyway）

**arrival（到店登记）**
- `ah_no` PK varchar(24)：AH + yyyyMMdd + - + 6 位查库序号（仿 WD/WO 生成器）
- `status` varchar(16) not null：WAITING/TRIAGED/CALLED/DONE/LEFT（英文短码，沿 writeoff 先例）
- `customer_id` varchar(16) not null；`store_code` varchar(16) not null
- `channel` varchar(16) not null：WALK_IN/REFERRAL/MARKETING/APPOINTMENT
- `queue_no` int not null：**本店当日递增**（max(queue_no)+1，条件 store_code + 当日）
- `note` varchar(256)；`appt_no` varchar(24)（预约来源幂等键，唯一约束语义靠先查后插）
- `arrived_at` timestamptz not null；`called_at`/`done_at` timestamptz
- `operator` varchar(32) not null（JWT）；`created_at` timestamptz not null
- 索引：(store_code, arrived_at)

**triage（分诊单，与 arrival 一对一——本批每次分诊 upsert 当前分诊单；改派不新增行）**
- `tr_no` PK varchar(24)：TR + yyyyMMdd + - + 6 位查库序号
- `arrival_id` varchar(24) not null（ah_no）；`customer_id` varchar(16) not null；`store_code` varchar(16) not null
- `type` varchar(16) not null：CONSULT/MEDICAL/SERVICE
- `assigned_to` varchar(32) not null（工号）；`forwarded_to` varchar(32)
- `note` varchar(256)；`plan_id` varchar(24)（同事务建的 CP 草稿号，回挂）
- `edited_by` varchar(64)；`edited_at` timestamptz
- `created_by` varchar(32) not null；`created_at` timestamptz not null

**emr_record（病历独立域）**
- `emr_no` PK varchar(24)：EM + yyyyMMdd + - + 6 位**查库序号**（替换 ConsultPlanService.nextEmrNo 的 nanoTime 取号——B27 缺陷修复；旧号 EM20260909-123456 同为 12 位前缀，like 查库天然兼容）
- `customer_id` varchar(16)；`customer_name` varchar(64) not null（无 customerId 自由建档名也存）
- `store_code` varchar(16) not null
- `type` varchar(16) not null：FIRST_VISIT/FOLLOW_UP/TREATMENT/PROCEDURE
- `visit_date` date not null；`status` varchar(16) not null：DRAFT/SIGNED/ARCHIVED
- `chief_complaint`/`present_illness`/`past_history`/`allergy`/`diagnosis`/`treatment`/`prescription` 均 TEXT
- `doctor_id` varchar(32)；`doctor_name` varchar(64)（签名时盖 JWT 人；顾问建草稿可空）
- `related_appointment_no`/`related_order_no`/`consult_id`(=plan_id) varchar(24)
- `version` int not null default 1；`parent_id` varchar(24)（修订源 emr_no）
- `signed_by` varchar(32)；`signed_by_name` varchar(64)；`signed_at` timestamptz
- `created_by` varchar(32) not null；`created_at`/`updated_at` timestamptz not null
- 索引：(store_code, status)、(customer_id)、(consult_id)

### 2.2 端点

**ArrivalController `/api/txn/arrivals`**（bizType=ARRIVAL）
- `GET /` reception:view / queue:view（OR）：params date(默认今天)/storeCode/status；DataScope.storeSpec 强制门店域；显式他店码→404；读模型批量富化 customerName/phoneMask（ApptRefNameResolver）、assignedToName（org name-map）、内联当前 triage
- `POST /` reception:edit：body{customerId,channel,note?,apptNo?}；校验客户/门店存在（name-map）；渠道白名单；queue_no 本店当日 max+1；apptNo 幂等（同 appt_no 已有→返回当前态不报错）
- `POST /{ahNo}/triage` reception:edit：body{type,assignedTo,note?}；状态机 WAITING→TRIAGED（CALLED 回退后再分诊也允许：TRIAGED 视为改派走 reassign）；**OrgStaffClient.fetchStaff 硬校验被分派人在职**（失败 400/502，同 writeoff 双签口径）；类型白名单；MEDICAL 被分派人须医疗资质（fetchStaff 返回 roles/primaryRole=DOCTOR；不符 400 中文）；同事务：
  1. upsert triage 行（plan_id 回挂）
  2. 内部直调 `ConsultPlanService.saveDraft`（不经 HTTP，不受前台无 consult:edit 限制）：customerId/storeCode 取 arrival；consultantId = type=MEDICAL ? 留空 : assignedTo；doctorId = type=MEDICAL ? assignedTo : 空；arrivalId=ahNo；空草稿（无结论/无项目，saveDraft 本就允许空草稿）
  3. audit ARRIVAL TRIAGE（payload 含 type/assignedTo/planId）
- `POST /{ahNo}/reassign` reception:edit：body{newAssignedTo,crossStore?}；crossStore 闸门：设置中心无后端，本批**后端不拦跨店改派但要求新被分派人在职**（跨店策略仍由前端 config 门控，交付说明逐条披露）；同步更新 triage.plan_id 草稿的 consultant/doctor？——**不更新**（草稿归属保留初诊人，改派仅改 triage.forwarded_to 与列表负责人；mock 同口径：mock 也未动 consultation）
- `POST /{ahNo}/call` queue:edit：TRIAGED→CALLED（幂等：已 CALLED 返当前态）
- `POST /{ahNo}/done` queue:edit：TRIAGED/CALLED→DONE（幂等 DONE 返当前态）
- 状态非法一律 400 中文；越权统一 404

**预约签到挂接**：AppointmentController.checkIn 现有事务内追加 `arrivalService.createFromAppointment(saved)`（同 writeoff 挂接同款，channel=APPOINTMENT、apptNo 幂等）。注意：仅当客户是建档客户（预约必有 customerId）；写失败随事务回滚（与 writeoff 任务同生共死，医疗主链一致性优先；name 解析类软失败不影响）。

**EmrController `/api/txn/emr`**（bizType=EMR）
- `GET /` emr:view：params storeCode/status/customerId/consultId；**数据域 storeSpec("store_code") 门店全见**（医生/顾问 SELF 不缩本人——对齐 mock「本店病历全见」活规格；DOCTOR/CONSULTANT 在 PermissionMatrix 数据域为门店/SELF 混合，沿用 consult_plan 的 SELF 收缩会破坏 EmrView 三 tab，故本域一律门店域；逐条交付披露）；富化 customerName（customerId 空时用落库 customer_name）
- `GET /{emrNo}` emr:view：越权 404
- `POST /` emr:create：见 1.3；校验：customerId 非空时客户存在；storeCode 取 JWT 本店（不信入参门店——body 不传 storeCode，由后端 current().storeId 落；前端适配层不传）；consultId 非空时二次校验方案五态+客户一致（读 PlanRepository，状态白名单）；emrNo 查库序号；version=1；audit CREATE
- `POST /{emrNo}/draft` emr:edit：仅 DRAFT；7 字段可空更新（草稿）；updatedAt
- `POST /{emrNo}/sign` emr:edit：仅 DRAFT；diagnosis+treatment 必填（400 中文）；盖 signed_by=JWT staffId、signed_by_name=org name-map 解析（失败回落 staffId）、signed_at=now；→SIGNED
- `POST /{emrNo}/archive` emr:edit：仅 SIGNED→ARCHIVED
- `POST /{emrNo}/revise` emr:create：源单非 DRAFT；复制新行：version=src.version+1、parent_id=src.emr_no、emr_no=查库新号（**不用 src+R{n} 拼号**——EM+日+序号体制下无法再拼 -R；前端 mock 的 -R 显示契约由适配层把 version>1 显示为「源号-R{version}」？——**决策修正**：为零改动满足模板显示 `r.emrNo`，新号直接存 `src.emrNo + '-R' + (src.version+1)` 作为 PK（varchar(24) 够长：EM20260909-000001-R2=19 字符）。修订号不进查库序号池，查库 max 时 like 'EMday-%' 不会匹配带 -R 的号，互不干扰）；清签名字段、status=DRAFT、customerName 等字段复制

### 5.5 运行态缺陷修复 2 项（随后端卡 759990d 入库）
