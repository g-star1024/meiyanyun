- 日期：2026-09-06
- 上批：P3-B8（财务运维报表 CSV 只读导出）
- 本批性质：finance-service 新增薪酬提成域（3 张业务表 JPA ddl-auto + 种子数据初始化器，不进 Flyway）、txn-service 新增提成业绩基数跨域内部端点、前端提成页由 mock 全切真实 API + 规则维护区 + 薪酬配置抽屉、员工管理页新增薪酬抽屉、咨询工作台本单提成预估接 estimate API；seed/prod 双栈真实验证 + Chrome DevTools 浏览器端到端。

## 一、本批目标与边界

### 1.1 目标（设计 §五 B9）

把「咨询师/医生薪酬提成」从前端 mock 活规格落为后端真实域，满足用户「后台设置好每个咨询师的薪酬+提成比例」：

1. **提成规则后台可配**：超额累进阶梯（tiers[{min,rate}]，rate 万分位）、基数口径（WRITEOFF 划扣确认收入 / ORDER 收款 / RECHARGE 充值预留）、适用角色（咨询师/医生/美容师）；规则可停用、可新建，调整不追溯历史期间。
2. **一人一薪配置**：每名员工一条当前生效薪酬配置（月底薪 Long 分 + 适用提成规则，规则可空=无提成），按生效月（yyyy-MM-01）幂等更替，同生效月重复保存=旧单转 INACTIVE、新单 ACTIVE。
3. **月度提成单**：按自然月 × 门店 × 人生成 DRAFT 提成单（业绩基数跨 txn 域取数、按规则超额累进试算），状态机 DRAFT→SUBMITTED→APPROVED→PAID，SUBMITTED→REJECTED；生成只建/重算 DRAFT，不覆盖已提交单。
4. **咨询台本单预估**：开单时按接诊咨询师当前生效规则对本单金额超额累进试算，仅预估不落账；未配置/异常诚实隐藏不打扰开单。
5. **资金红线**：计提/试算/审批**只产生成本镜像（commission_record），绝不在 fund_entry 生成资金实付分录**；PAID 仅镜像外部薪酬系统回传状态，不划款。

### 1.2 边界红线（本批不碰）

- 不做分项目比例（注射/光电/护理差异费率）、新客/复购差异、团队+个人分成——设计 §87-90 明列为一期不做项。
- RECHARGE 充值基数口径一期不实现（内部端点预留，规则选该基数时按 0 分量诚实处理）。
- 不接外部薪酬系统实付：PAID 为状态镜像，不触发任何资金划付。
- 零样式改动：提成页/员工页/咨询台均沿用既有卡片与抽屉样式，仅接真实数据与新增既有样式的抽屉。

## 二、改动清单

### 2.1 finance-service（新增薪酬提成域）

新增 11 个文件（均为业务表，JPA ddl-auto 自动建表，种子不进 Flyway）：

- **实体**：
  - `CommissionRule.java`：提成规则（ruleId、ruleName、base 基数口径、role 角色、tiersJson 超额累进阶梯、active 停用开关、审计字段）。
  - `StaffCompConfig.java`：员工薪酬配置（compId、staffId、staffName、storeCode、baseSalary 月底薪分、commissionRuleId 可空、effectiveMonth 生效月、status ACTIVE/INACTIVE、审计字段）。
  - `CommissionRecord.java`：月度提成单（commissionNo、month、storeCode、staffId、staffName、ruleId/ruleName 快照、baseAmount 业绩基数分、commissionAmount 提成额分、tiersSnapshot 阶梯明细、综合提成率、状态机字段、提交/审批/支付人时间、驳回原因）。
- **仓库**：`CommissionRuleRepository` / `StaffCompConfigRepository` / `CommissionRecordRepository`（Spring Data JPA）。
- **`CommissionService.java`**（核心领域服务）：
  - 规则：list / create / update（校验 rate 万分位 0-10000、阶梯 min 递增、基数/角色合法；停用不删历史）。
  - 薪酬配置：list（当前生效）/ save（校验 staffId/staffName/storeCode 非空、底薪分 0-100,000,000；同 staffId+effectiveMonth 幂等更替：旧 ACTIVE→INACTIVE，新单 ACTIVE）。
  - 提成单：list / generate（跨 txn 取业绩基数 → 按规则 base 取分量 → 超额累进试算，只建/重算 DRAFT）/ submit / approve / reject / markPaid（状态机非法跃迁 422 BUSINESS_ERROR）。
  - estimate：按 staffId 查当前生效配置+规则，对单笔 amount 超额累进试算，返回 configured/ruleName/segments；未配置返回 configured:false（不抛错）。
  - 业绩基数跨域取数：RestTemplate + X-Internal-Token 调 txn 内部端点，**失败降级空集合**（不臆造业绩）。
- **`CommissionController.java`**（`/api/finance`，类级 `finance:commission:view`）：

  | 端点 | 权限 | 说明 |
  | --- | --- | --- |
  | `GET /comp-configs` | view | 当前生效薪酬配置列表 |
  | `POST /comp-configs` | `finance:commission:edit` | 保存薪酬配置（幂等更替） |
  | `GET /commission-rules` | view | 规则列表 |
  | `POST /commission-rules` | edit | 新建规则 |
  | `POST /commission-rules/{ruleId}` | edit | 更新/停用规则 |
  | `POST /commission/generate` | edit | 月度生成/重算 DRAFT |
  | `GET /commission` | view | 提成单列表 |
  | `POST /commission/{id}/submit` | edit | DRAFT→SUBMITTED |
  | `POST /commission/{id}/approve` | `finance:commission:approve` | SUBMITTED→APPROVED |
  | `POST /commission/{id}/reject` | approve | SUBMITTED→REJECTED |
  | `POST /commission/{id}/mark-paid` | approve | APPROVED→PAID |
  | `POST /commission/estimate` | view **或** consult:create/edit/view（任一） | 本单预估（咨询师开单可用，无财务权限亦可） |
  | `GET /export/commission.csv` | view | 薪酬表 CSV 导出（复用 B8 BOM/RFC4180 模式） |

- **`CommissionNoGenerator.java`**：提成单号 / compId / ruleId 生成（yyyyMMdd 序列）。
- **`CommissionDataInitializer.java`**：种子播种（count>0 跳过，不进 Flyway）——CR-SEED-001 咨询师阶梯 6/8/10/12%（base=WRITEOFF）、CR-SEED-002 医生 10/12%；12 条在岗咨询师/医生薪酬配置（effectiveMonth=2026-07-01，分属 SST01~SST06，底薪 8000-15000 元）；当月 36 条演示提成单（DRAFT/APPROVED 混合）。

## 五、问题与教训（归档必录）

### 5.1 薪酬配置保存 422「所属门店不能为空」（本批缺陷，已修复并双链路验证）

- **现象**：提成页薪酬配置抽屉保存 → 422 BUSINESS_ERROR「所属门店不能为空」。
- **根因**：后端 `CommissionService.saveCompConfig` 校验 storeCode 非空（契约要求）；前端 `FinCommissionView.vue` 提交体 `storeCode: staff?.storeCode ?? null`，而演示员工 E001~E014 的 `Staff.storeCode` 为 `string | null`（员工页归属门店列显示「—」），导致传 null 被后端拒绝。`T1StaffView.vue` 员工页薪酬抽屉存在**同源缺陷**（`storeCode: s.storeCode ?? null`）。
- **修复**：两处改为 `staff?.storeCode || storeCtx.currentStoreCode`——引入全局门店上下文 `useStoreContext`（`stores/storeContext.ts`，currentStoreCode 默认 'SST01'，main.ts / App.vue 启动即 init() 恒有值，是 inventory/finInvoice/finCost 等写接口 storeCode 的标准兜底来源）。
- **验证**：构建通过 → seed 前端部署（指纹 index-C22Zckkr.js）→ 提成页保存 reqid=122 [200]（请求体 storeCode="SST01"）、员工页调薪 reqid=163 [200]；修复后同步部署 prod 前端（8080，同指纹），双栈一致。

### 5.2 环境/工具事实备忘

- Chrome DevTools MCP `evaluate_script` 参数名是 **`function`**（值为 JS 函数字面量 `async () => {...}`），不是 `expression`；误传报 "Required at function"。
- 登录接口字段是 **`loginName`**（非 username/staffNo），响应 token 在 JSON 顶层 `token`；列表端点返回裸数组。
- CSelect 自定义下拉可靠操作：`trigger.click()` → 等 350ms → 按文本找 `.csel__opt` li.click() → 等 300ms；input 填值用 native setter + dispatch input/change。
- 网关 :18443/:8443 为纯 TLS 端口，curl 须 `-sk` 且 `export no_proxy='*'`（本机 Clash 7890 代理）。
- 咨询台接诊草稿（待咨询/咨询中）后端暂无草稿/接诊端点，为 mock 演示，草稿咨询师 id 为 `staff-lin`；浏览器验证正向预估时为该 mock id 建了薪酬配置（SC20260906-000003，留存 seed 演示库，使演示咨询师也能展示预估条）。
