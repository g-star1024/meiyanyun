## 1. 背景与目标

客户画像引擎页（`/ai/profile`）按**画像输出 / 特征权重 / 效果回看**三 tab 组织 AI 客户洞察能力，卡1 之前整页是硬编码 mock：四 KPI 写死、客户候选写死、AI 生成画像只回填本地假文案、价值分/分群/标签/特征权重/周成功率全部前端造假，「应用到分群」按钮无任何后端动作。

与 B46 话术库不同，画像需要**客户域的真实档案与消费事实**支撑，因此本卡除了在 ai-service 落画像资产表，还必须打通 ai→customer 的跨服务只读富化（铁律：禁止 JdbcTemplate 直读别域表，服务间走 RestTemplate + X-Internal-Token，远程失败降级不阻断）。出站生成仍复用现成 invoke 全治理链，不平行造一套。

B47 卡1 验收口径：

1. 客户候选按中文姓名/手机号片段真实搜索（跨服务），选中后 AI 画像走**真实火山方舟 ark-code-latest**，画像（价值分/分群/标签/理由）落新表并与 invoke 日志同源关联；
2. 复用既有 invoke **全治理链**（功能启用/角色灰度矩阵 / 门店灰度 / 敏感词拦截 / 配额 / 模型校验 / 计费 / ai_invoke_log），不平行造一套出站；
3. 四 KPI（覆盖客户数/标签数/画像调用数/应用分群数）全部真算，历史列表、最近画像真实读取；
4. 特征权重 Top8 SHAP、近 4 周调用成功率回看全部来自真实结构化结果 / append-only 日志按周边界聚合，无调用周诚实空态；
5. 「应用到分群」幂等置位并写审计，重复应用 `changed:false`；
6. 页面样式主体零改动、复用既有 C 组件，真实生成长等待期间按钮置灰防重复提交。

## 5. 真验过程发现与修复

1. **中文客户名搜索静默 200 返空（跨服务编码缺陷，代码修复）**：CustomerProfileClient 首版用 RestTemplate 直接拼 `?keyword=张女士`，RestTemplate 默认按 ISO-8859-1 编码 query，customer 侧按 UTF-8 解析得到乱码，候选查询**不报错却静默返空**。分层隔离（直连 customer 内部端点用 curl 带正确编码可命中）确认缺陷纯在 ai→customer 一跳。修复：改用 `UriComponentsBuilder.fromHttpUrl(...).queryParam("keyword", kw).encode(StandardCharsets.UTF_8).build().toUri()` 显式 UTF-8 编码，并走 `restTemplate.exchange(URI, ...)` URI 重载（不再经 String 模板二次编码）。重建后「张女士/张/手机号片段」三类搜索均真实命中。
2. **效果回看周聚合变累计计数（边界缺陷，代码修复）**：首版周窗口只有下界条件，跨周边界重叠导致每周把历史调用累计进去（W1~W4 都显 7）。修复：AiInvokeLogRepository 新增 native `aggregateBetween(start,end,featureCode)`，条件 `invoked_at >= :start and invoked_at < :end`（**含下界、不含上界**），review 按近 4 周边界逐周分桶。重建后 W1/W2/W3 空态、W4=7 次 71.43%，近 4 周平均 71.4%，UI 层坐实。
3. **静态镜像必须重建（环境坑，沿用既有经验）**：.vue/.ts 改动只有 build + `--build frontend` 后才在 8080 生效；ai-service/customer-service 改 Java 须先宿主 mvn package 出 fat-jar 再 compose build + force-recreate（backend/Dockerfile 复制宿主 jar）。
