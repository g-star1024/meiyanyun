## 二、里程碑排序与范围（建议）

### 🥇 M7 · 权限与安全（P0，建议立即开工）

**为什么排第一**：① 规划明定 P0；② 后端零鉴权是当前最大安全敞口，且 M4 退款/退卡等资金类接口已上线裸奔，越权风险随真实写链路增多而放大；③ 前端 v-perm 已完整但后端空心，权限模型不定，后续每个新域写接口都要返工加鉴权——先立法后修路成本最低；④ `permission-matrix.md` 设计稿已备，可直接落地。

| 工作项       | 层      | 范围                                                                                                                          | DoD 要点                                        |
| --------- | ------ | --------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------- |
| RBAC 数据模型 | 后端 org | 新建 `role_permission`（role\_code + resource + action）、`permission_def` 资源动作字典；RoleDef 对齐 8 角色（**剔除 STORE\_MANAGER**，与前端矩阵对齐） | schema 幂等双库；种子角色权限全量灌入                        |
| 鉴权拦截      | 后端     | 统一鉴权切面/拦截器：从请求头解析当前用户角色（`?as=` 模拟 → 后续接登录态），按 resource+action 校验；**全站写接口先加 @PreAuthorize/注解**                               | 横向越权（他店数据）、纵向越权（低角色调高权限接口）用例 curl 全过；403 中文错误 |
| 数据权限      | 后端     | data\_scope（本店/本区域/集团）过滤注入列表查询                                                                                              | 门店店长只见本店、区域经理见辖区、集团见全部                        |
