## 2. 影响面只读核实（卡0 侦察结论）

- **落点唯一＝customer-service**：DsarRequest/Customer/ConsentService 同服务、CustomerRepository/DsarRequestRepository 直接查询；audit 走 customer-service 既有通道 `AuditRecorder.record(bizType, ..., action, payload)`；marketing-service 仅 CustomerConsentClient＋PushService 两文件参与（撤回联动调用方），不新增 marketing 端点。Job 与仓库同服务直接查询，无需跨服务 RPC 巡检。
- **设计稿两处实证订正（铁律 0）**：
  1. `customer_id` 类型设计稿写 BIGINT，实证 [Customer.customerId](file:///Users/huluobo/WorkBuddy/2026-08-15-23-51-02/meiyun-platform/backend/customer-service/src/main/java/com/meiyun/customer/Customer.java) 为 String(16)，dsar_request.customer_id 对齐 String(16)；
  2. DELETE 不能用 customer.status=DEACTIVATED（既有 CHECK 约束只允许活跃/沉睡/流失），改为 fulfillment_data 软删标记语义；
  另 ACCESS 不复用 ai_privacy_export（那是审计区间哈希导出非客户个人信息导出），改为 customer-service 内 ObjectMapper 序列化。
- **DataScope 门店域**：dsar_request 表无 store_code 列，列表按 storeCode 过滤改为「先查本店客户 ids 再 Specification in」；跨店越权统一 404 中文（不泄露数据是否存在）；consent 端点 requireReadable 复用 `DataScope.canReadOwned(storeCode, ownerStaffId)`。
- **审计基座可复用**：customer-service 已有 RestAuditRecorder/AuditRecorder 落 JSON payload，本批 DSAR/CONSENT/COMPLIANCE 三 bizType 直接复用；audit_log append-only 不变。
- **营销撤回联动的内网红线**：consent 状态属客户隐私，仅以系统身份（X-Internal-Token，`internal:customer-directory`）开内部端点，营销侧经 RestTemplate 带内网 token 调用；撤回后 skipped 跳过推送。
- **巡检与调度基座**：customer-service 已有 @Scheduled 任务（LevelMonthlyJob 等），本批 Job 沿用 Spring 调度＋cron 属性外置（`meiyun.compliance-inspection.cron` 可配），无新依赖。
