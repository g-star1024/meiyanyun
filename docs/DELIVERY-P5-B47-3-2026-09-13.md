## 1. 背景与目标

流失预警模型页（`/ai/churn-model`）按**批次评分 + 风险榜 + 关键因子 + 联动建议**组织 AI 流失洞察能力，卡3 之前整页是硬编码 mock：三 KPI 写死、风险榜写死、点「运行评分」只回填本地假分数/假等级、「登记干预」按钮无任何后端动作、六因子权重与联动目标全部前端造假。

与卡2 复购相同，流失评分的输入事实主要在**交易域**（最近到店间隔、到店频次、近期消费、客诉等），本卡打通 ai→txn 一条跨服务只读富化（候选客户 + 近期到店/消费事实）：ai-service 经 RestTemplate + X-Internal-Token 调 txn-service 内部端点，远程失败降级不阻断 AI 出站。出站推理仍复用现成 invoke 全治理链，不平行造一套；批次是**逐客户串行真实推理**（非批量假算），每个客户一条 ai_invoke_log、一行预测快照。与卡2 的周期（周/月/季）维度不同，流失榜**不设周期维度**——服务端按 `prediction_id DESC` 取最近一批即「当前风险榜」，重复运行产生新批次、榜单始终读最新批次。

B47 卡3 验收口径：

1. 对真实候选客户**逐客户**走真实火山方舟 ark-code-latest 推理流失风险分/等级/结构化流失信号并落新表批次快照，与 invoke 日志同源关联；
2. 复用既有 invoke **全治理链**（功能启用/角色灰度矩阵 / 门店灰度 / 敏感词拦截 / 配额 / 模型校验 / 计费 / ai_invoke_log），不平行造一套出站；
3. 三 KPI（本批客户数/平均流失分/已登记干预数）全部真算，风险榜、当前批次概要真实读取，风险等级筛选（high/mid）真实生效；
4. 六因子中暂无数据源支撑的因子（客诉、互动）`available=false` 置灰、权重条宽 0%，不伪造；
5. 「登记干预」行内与批量均幂等置位并写审计，重复登记 `changed:false`/affected=0 不重复写审计；
6. 页面样式主体零改动、复用既有 C 组件，逐客户长推理期间按钮置灰防重复提交，无批次时诚实引导空态。

## 5. 真验过程发现与修复

1. **风险等级列三行全显「低风险」——前端列 key 与会员等级字段撞名（真实缺陷，已修复）**：A1ChurnView 风险榜列定义 `{ key: 'level', label: '风险等级' }`，而 ChurnRow 上 `level` 字段是**会员等级**（黑卡/普通/金卡）；CTable 列插槽 `#col-level="{ value }"` 注入的 value 实际是会员等级（如「黑卡」），`riskLabel('黑卡')` 落入兜底分支返回「低风险」，致真实 mid 三行全部误显低风险。修复为插槽取整行：`#col-level="{ row }"` 后用 `row.riskLevel` 计算 `riskLabel(row.riskLevel)` 与状态色；npm run build + 重建 frontend 镜像 + 硬刷新后三行正确显「中风险」。教训：CTable 列 key 必须取该行实际字段名，语义标签列（风险等级）与实体同名异义字段（会员等级）需在适配层避让。
2. **churn 绑定误指 benchmark 模型致首次 /run 全批 404（运行时配置缺陷，已修正）**：bindingId=2 的 model_id=2 是 ark-code-benchmark，供应商对该模型返回 404「does not support the agent plan feature」；UPDATE 改绑 model_id=1 ark-code-latest 后打通。失败调用按治理链设计如实沉淀 ai_invoke_log（id=30 success=f），成功批次 id=31~33 并存，append-only 不删。
3. **登录响应 token 在顶层字段（工具用法更正）**：`POST /api/org/auth/login` 响应为顶层 `{"token":"..."}`，脚本按旧口径取 `["data"]["token"]` 会 KeyError；改解析 `["token"]` 成功。
4. **ai_invoke_log 列名踩坑（工具用法）**：该表无 status/duration_ms 列，真实列为 `success`(boolean)/`latency_ms`/`cost_fen`；误用 status 查询报 column does not exist，经 `\d ai_invoke_log` 核对后重查成功。
5. **截图落盘受沙箱限制（环境坑，沿用既有经验）**：`take_screenshot` 的 filePath 受 workspace roots 白名单限制（仓库父目录、仓库根均不能落盘），改为以可访问性快照文本 + Network 请求留证。
6. **历史既有坑（本卡沿用）**：静态镜像必须重建（.vue/.ts 改动 build + `--build frontend` 后才在 8080 生效）；compose 应用栈必须带 `-f docker-compose.app.yml`；zsh 中 URL 查询参数 `?` 需引号包裹。
