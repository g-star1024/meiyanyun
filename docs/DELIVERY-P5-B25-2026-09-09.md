### 1.2 边界红线（铁律 / 红线约束）

- **B24 隔离**：严格不触碰 B24 文件——txn-service 的 `InternalFinanceController` / `ConsultPlan` / `PlanRevision` / `FinanceFlowDTO`、finance-service 全套、customer-service 的 `InternalCardController` 及 Card* 文件均未改动。txn-service 仅**新增 1 个独立文件** `InternalOrderController`（只读内部端点），与 B24 零耦合。

- **审计 payload 必为合法 JSON**（jsonb）：所有新增审计均手工拼 JSON 并转义。
- **幂等**：发分 clientToken=`AUTOPOINTS:{orderNo}`、回退=`AUTOPOINTS_REFUND:{orderNo}`，复用 `PointsLedger.client_token` 唯一判重；标签打标受复合主键约束 + `Conflict` 捕获。
- **不碰资金池**：自动积分只动 `customer.points` 与积分池月度累计，绝不触达资金/储值余额（CARD_SALE 售卡订单已排除，见 §2.2）。
- **双端/Token 不变**：纯后端自动化，无前端页面改动，不涉及 UI Token 与样式。

## 二、接口与状态契约

### 2.1 标签自动化规则（base path：`/api/customer/tag-rules`）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/tag-rules` | `tag:view` | 规则列表（分页，priority 排序） |
| POST | `/tag-rules` | `tag:edit` | 新建规则（四件套校验 + 目标标签存在性） |
| PUT | `/tag-rules/{ruleId}` | `tag:edit` | 更新规则（局部字段） |
| DELETE | `/tag-rules/{ruleId}` | `tag:edit` | 删除规则 |
| POST | `/tag-rules/{ruleId}/run` | `tag:edit` | 手动执行单条规则（即时扫描全部客户） |
| POST | `/tag-rules/run-all` | `tag:edit` | 手动执行全部启用规则 |

条件类型 `condition_type`：`CONSUME_GTE`（累计消费≥元）/ `VISIT_GTE`（到店次数≥）/ `POINTS_GTE`（积分≥）/ `LEVEL_IN`（等级命中逗号清单）/ `CHANNEL_EQ`（渠道=）。
效果 `effect`：`ASSIGN`（命中打标）/ `REVOKE`（命中撤标）；`revoke_when_unsatisfied=true` 时 ASSIGN 规则在条件不再满足时自动撤标。
审计：`TAG_AUTO` / CREATE·UPDATE·DELETE·RULE_RUN·RULE_RUN_ALL。

### 2.2 消费自动积分（引擎，无新增业务 HTTP 端点；定时任务驱动）

- 数据源（新增 txn 只读内部端点，见 §2.4）：`GET /api/txn/internal/paid-orders?from=&to=`、`GET /api/txn/internal/refunded-orders?from=&to=`。
- 积分折算：`points = floor( (amount分/100) × point_rule.earn_rate × level_rule_config.points_multiplier )`，两乘数缺省各为 1。
- 发分：`adjustPoints(customerId, +pts, "消费自动积分（订单 X）", "AUTOPOINTS:{orderNo}")`。
- 回退：`adjustPoints(customerId, -pts, "退款回退积分（退款单 X）", "AUTOPOINTS_REFUND:{orderNo}")`；余额不足时跳过（留人工调平，不制造负分）。
- 排除 `biz_kind=CARD_SALE` 订单（售卡/充值不计入消费积分，防充值循环积分）；排除在积分引擎发分侧强制执行（`AutoPointsService` 循环内跳过），txn 投影端点保持通用、不绑业务策略。
- 游标：`auto_points_state`（单行 id=1）记录 `last_run_at`，断点续跑、不重复扫描；txn 不可用则跳过本轮、下轮自愈。
- 审计：`POINTS` / AUTO_POINTS（有实际发/退分时）。

### 2.3 等级定时批处理（引擎，复用既有手动端点逻辑）

- 触发：`@Scheduled(cron = "0 5 0 1 * ?")`（每月 1 号 00:05）。
- 收敛：读 `level_rule_config.auto_upgrade`，关闭则跳过本轮。
- 执行：调用既有 `CustomerService.autoUpgrade()`（只升不降），升级>0 时落 `LEVEL` / AUTO_UPGRADE 汇总审计（payload 与手动端点 `POST /api/customer/member-levels/auto-upgrade` 完全一致）。
- 审计 actor：定时任务统一记 `SYSTEM`。

### 2.4 新增 txn 内部只读端点（base path：`/api/txn/internal`）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/paid-orders?storeCode=&from=&to=` | `internal:finance-flow` | 已收款订单精简投影（orderNo/customerId/storeCode/amount分/status/bizKind/createdAt） |
| GET | `/refunded-orders?storeCode=&from=&to=` | `internal:finance-flow` | 已退款流水精简投影（txnNo/orderNo/customerId/storeCode/refundAmt分/createdAt） |

- 权限复用 `internal:finance-flow`（系统身份 X-Internal-Token 已具备，无需新增权限种子）。
- **与 B24 `InternalFinanceController` 相互独立、互不依赖**，仅新增只读投影，不修改任何 B24 文件。
