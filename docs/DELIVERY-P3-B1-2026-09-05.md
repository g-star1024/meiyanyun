## 一、本批目标与边界

**目标**：M6 财务台账页长期全量 mock（seed 假数据），真实经营数据看不见。本批在**不新增任何资金写动作**的前提下，把已存在于 txn / customer 两域的真实经营数据，经服务间内部端点投影到 finance-service 读时聚合，接通前端财务台账类页面。

**边界（红线）**：
- finance-service 维持**纯只读**（9 个 GET，零 POST/PUT/DELETE）；
- 不直读别域表：跨服务取数一律 RestTemplate + `X-Internal-Token`（禁 JdbcTemplate 跨域）；
- 样式零改动：前端仅换数据源，适配层消化字段差异；
- UI 模型 ≠ 后端能力处**诚实降级**，不伪造数字（成本/毛利/评级等无数据源的位置显式「待接入」）。

## 三、seed 栈两起环境修复（部署阻塞实证）

### 3.1 compose 重建后跨服务 URL 环境变量丢失

- **现象**：seed compose 重建后 finance 聚合全空，日志持续降级 WARN。
- **根因**：finance 的 `txn.service.url` / `customer.service.url` 走环境变量注入，重建容器时未带上 seed 锚点（`docker-compose.seed.yml` L31-48），回落默认 `127.0.0.1:8083/8082` 指向容器自身。
- **修复**：compose env 补 TXN/CUSTOMER_SERVICE_URL 指向 seed 网络内服务名；`docker compose up -d` 重建（**docker restart 不重读 compose env，必须重建容器**——已沉淀为操作纪律）。

### 3.2 Flyway V3 历史校验和为 NULL 导致 customer 容器启动即退出

- **现象**：seed customer-service 容器反复退出；日志 Flyway validate 失败：V3（marketing_tables）期望 checksum 555074252，`meiyun_seed.flyway_schema_history` 中该记录 checksum 为 NULL。txn/finance 无 Flyway 迁移（JPA ddl-auto）不受影响、已 healthy。
- **事实核验（修复前）**：查 seed 库 coupon_template / campaign 全部列与 CHECK 约束，确认表结构**已是 V3 英文状态机形态**（与 prod 同版本）——迁移实际已生效，仅历史表校验和缺失（历史遗留）。
- **修复**（Flyway repair 语义）：
  ```sql
  UPDATE flyway_schema_history SET checksum = 555074252
  WHERE version = '3' AND checksum IS NULL;
  ```
  → `docker start` → 25 秒后 healthy。
- **教训沉淀**：种子库若经手工灌库/历史迁移中断，flyway_schema_history 可能缺 checksum；新 jar validate 前应先核对表结构与迁移文件一致，再补校验和，禁止盲目 repair 或删历史行。

## 五、本批明确不做（移交 P3 后续批次）

以下为调研确认的**真实缺口**，本批按红线不触碰，设计见 `docs/DESIGN-P3-FINANCE-LATER-2026-09-05.md`：

1. **支付渠道断点**：order_payment 每笔已落 pay_method（cash/card/wxpay/alipay/balance），但 txn 内部投影 OrderFlow 不带 payMethod、finance 订单分录 channel 硬编码 null（FinanceAggregationService L125），日报渠道全落「未标记渠道」。
2. **三张资金表空转**：outbox_record / account_mirror / prepay_pool 在整个后端**无运行时写入方**（无 save 调用、outbox 无枚举/CHECK）。
3. **退款终审不触发资金动作**：TxnService.confirmRefund 只改本地状态 + audit（javadoc 自认「资金出入账由 M6 补」），不通知 finance、不回写 member_card 状态。
4. **充值/储值链路缺失**：无开卡充值端点、无 member_card 余额变动台账表（points_ledger 有、card ledger 无）；PaymentService 列了 "balance" 支付方式但 pay() 全流程不扣 member_card.balance。
5. **成本域空白**：TK-MATERIAL/TK-DEPRECIATION/TK-LOSS/TK-LABOR 仅存在于前端 mock；后端无成本实体/表/端点；store 无库存耗材域；M4 划扣不联动库存；双签工单（耗材领用/报损/提成）审批通过后无动账。
6. **划扣历史查询缺条件**：GET /api/txn/writeoff 仅门店域 + 时间倒序，无 cardNo/customerId/from/to 参数（WriteoffRepository 无对应方法）。
