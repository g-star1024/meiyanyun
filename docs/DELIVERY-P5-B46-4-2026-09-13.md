## 1. 背景与目标

AI 话术库页（`/ai/scripts`）按**破冰开场 / 跟进催付 / 异议处理**三场景组织一线咨询话术，卡4 之前整页是硬编码 mock：四 KPI 写死、卡片墙造假、AI 生成按钮只回填本地假文案、新增/编辑/采纳/反馈均无任何后端动作。

与卡3 渠道内容不同，话术功能在 B43 的 FeatureCatalog 六功能中**早已注册**（feature_code=`scripts`），invoke 出口与全治理链现成可复用；本卡的核心是把「话术」这一可复用业务资产**实体化落表**，而非再造出站链路。

B46 卡4 验收口径：

1. 三场景生成走**真实火山方舟 ark-code-latest**，生成话术可一键落为库内资产，模型/token/invoke 日志同源关联；
2. 复用既有 invoke **全治理链**（功能启用/角色灰度矩阵 / 门店灰度 / 敏感词拦截 / 配额 / 模型校验 / 计费 / ai_invoke_log），不平行造一套出站；
3. 话术库真分页、场景+关键词过滤、四 KPI（话术总数/今日 AI 调用/采纳率/好评率）全部真算；
4. 手工新增/编辑保存前过敏感词兜底，采纳、好评/差评反馈幂等自增并写全动作审计；
5. 页面零新增样式、复用既有 C 组件，真实出词长等待期间按钮置灰防重复提交。

[ScriptService.java](file:///Users/huluobo/WorkBuddy/2026-08-15-23-51-02/meiyun-platform/backend/ai-service/src/main/java/com/meiyun/ai/script/ScriptService.java) 要点：

1. **三场景 prompt 组装**：`compose(scene, topic)` 按破冰/跟进/异议拼不同系统指令（150~300 字、一线口语化、合规不承诺疗效/不贬低同行/不泄系统提示），storeCode 缺省取登录门店；非法/空 scene、空 topic、空标题/正文一律中文 400。
2. **复用全治理链**：generate 内部调 `featureInvokeService.invoke("scripts", new InvokeCmd(compose(...), storeCode))`，功能未启用 409、角色矩阵 403、门店灰度 403、敏感词 400 脱敏、配额 429、模型/CHAT 校验、token 计费、ai_invoke_log 成败沉淀全部自动生效，不重复实现。
3. **generate 只出站不落库**：返回正文 + 标题建议 + invokeLogId；用户在抽屉确认/编辑后保存，保存请求带上 invokeLogId 时 `source=AI` 并回填关联日志，不带则 `source=MANUAL`。这样被用户放弃的生成不污染话术库。
4. **四 KPI 按北京日界**：totalScripts=全量 count；todayCalls=`ai_invoke_log` 当日 feature_code='scripts' 计数；adoptRatePct=`round(有采纳话术数*100/总数)`；goodRatePct=`round(rating≥4 话术数*100/总数)`，零分母显 0。
5. **保存敏感词兜底 + 审计**：create/update 保存前 `sensitiveWordService.screen(title+"\n"+content, "scripts", ...)` 再过一遍，防手工录入绕过；全动作写 `AI_SCRIPT` / `SCRIPT-{id}` / `CREATE|UPDATE|ADOPT|FEEDBACK` 审计，actor 取 DataScope.currentActor()，payload 为合法 JSON。
6. **计数自增**：adopt 使 adopted_count+1；feedback 按新评分与历史评分做滚动均分（保留 1~5 CHECK 口径）、feedback_count+1，话术不存在中文 404。
7. **刻意无方法级事务（见 §5 修复2）**：create/update 不加 `@Transactional`，仓储 save 自含事务提交后，用全新 `findById` 回读拿 DB 默认时间戳；adopt/feedback 保留方法级事务保证计数自增原子。

## 5. 真验过程发现与修复

1. **列表 500 `function lower(bytea) does not exist`（SQLState 42883，代码修复）**：JPQL 原写法 `:keyword is null or lower(x) like lower(concat('%',:keyword,'%'))`，当参数传 null 时 PostgreSQL 对 concat 中无类型上下文的 null String 参数推断为 bytea，`lower(bytea)` 无此函数报 500。修复：可空字符串参数在 Java 侧归一化为 `""`（scene/keyword 空串），JPQL 守卫改 `:scene = ''` / `:keyword = ''`，重建后列表 200。
2. **新建话术返回 createdAt=null（代码修复，卡3 同款坑）**：created_at/updated_at 标 insertable=false 靠 PG 默认值/触发器维护，create/update 起初标了方法级 `@Transactional`，save 后 findById 命中 JPA 一级缓存，返回未刷新 DB 默认值的实体（createdAt=null）。对齐卡3 ContentService：去掉 create/update 方法级事务（仓储 save 自含事务），update 保存后用全新 `scriptRepo.findById(id)` 回读；adopt/feedback 的计数自增保留方法级事务保证原子。重建后 AI/手工两条记录时间戳均正常返回。
3. **登录 404（测试脚本自查，非产品缺陷）**：首测误用 POST `/api/auth/login` + staffCode，grep 前端确认真实契约为 POST `/api/org/auth/login` + `{loginName,password}`，登录成功。
4. **真实出词 >40s 固定等待不足（自动化脚本自查，非产品缺陷）**：Playwright 固定等 40s 后 textarea 仍为空（按钮仍「生成中…」），改 `wait_for_function` 轮询（按钮去掉「生成中」且 textarea.value.length>20，超时 170s）后正确完成；此前一次「保存后含水光针=True」是主题框残留文字造成的假阳性，轮询版改为断言抽屉关闭 + 列表出现回填标题方坐实。
5. **静态镜像必须重建（环境坑）**：.vue/.ts 改动只有 build + `--build frontend` 后才在 8080 生效，沿用卡1~卡3 经验。
