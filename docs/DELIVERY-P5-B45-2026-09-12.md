## 5. 真验过程发现与修复

### 5.1 模型可选数字字段「清空保存」报错——numOrNull 修复（用户原始诉求）

[AiProvidersView.vue](file:///Users/huluobo/WorkBuddy/2026-08-15-23-51-02/meiyun-platform/frontend/src/views/AiProvidersView.vue) 原先对 number 输入框值直接 `trim()`，清空时数值为 `null/undefined`，`null.trim()` 抛错致「修改模型信息保存报错」。已在用户报障当刻修复（trim 报错修复先于 B43，提交见 ROADMAP）：统一走 `numOrNull(v)`（空串/空白→null、非有限数→null、否则转 Number），价格/温度/topP/优先级等可选数字字段空值安全，空值保存即清空列。

### 5.2 KPI「平均效果提升」不随结案更新——computed 派生修复（本卡真验新发现）

**现象**：实验结案后，页面 KPI「平均效果提升」仍显示结案前的 -80 pp，但实时接口已返回 0.00。

**根因**：KPI 数组 `kpis` 是 `loadKpi()` 内 `toKpis(k)` 生成的**一次性快照**，toKpis 在生成那一刻闭包读取 `evalStats.value`；结案流程只调用 `loadEvalStats()` 更新了 `evalStats`，并未重新执行 `loadKpi()`，`kpis` 数组引用不变、卡片不重渲染，停留在旧值。纯前端响应式缺陷，后端数据始终正确。

**修复**（[A1GovernView.vue](file:///Users/huluobo/WorkBuddy/2026-08-15-23-51-02/meiyun-platform/frontend/src/views/A1GovernView.vue#L42-L44)）：拆分为基准数据 `baseKpi = ref<AiKpi|null>`（loadKpi 只写它）+ `const kpis = computed(() => baseKpi.value ? toKpis(baseKpi.value) : null)`。toKpis 内读取 evalStats，evalStats 变化即触发 computed 重算，平均效果提升/运行中实验实时联动，无需在每个写操作后手动补 loadKpi。

**复验**：重载治理页，KPI 正确显示「平均效果提升 **0 pp**、运行中实验 0」，vue-tsc 通过、控制台零报错。

### 5.3 「价格清空后表格仍显旧值」证伪为测试工具限制，非产品缺陷

真验初期用 Chrome MCP 的 `fill` 工具把价格框填成空串后保存，UI 与 PG 仍显旧值，一度疑为空值链路缺陷。经后端代码审查（update 支持 BigDecimal null 差量置空）、curl POST null（changed:true、PG NULL）、浏览器真实键盘清空（落 NULL）三步定位：**MCP `fill('')` 不触发 Vue v-model 同步**（程序化设值未派发 input 事件），产品代码本身正确。相关 MCP 使用经验备忘：

- `fill` 工具参数名是 **value**（非 text）；fill 空串不同步 v-model，清空输入须 focus 后 type/press_key，或 evaluate 内 `el.select(); document.execCommand('delete')`；
- number 输入框 Meta+a 只删一个字符；
- `window.prompt/confirm` 必须用 MCP 真实 click（uid）触发后立即 handle_dialog；JS `el.click()` 触发的 prompt 会被浏览器手势策略抑制（不发网络请求）；handle_dialog 用 `promptText` 填入结论；
- 多抽屉叠加时用 `getBoundingClientRect().width>0` 定位唯一可见抽屉；evaluate_script 必须带 pageId。
